# Changelog

What changed in each version of md2html, newest first. The form is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/): what is not yet released waits under Unreleased, grouped as Security, Added, Changed, Fixed and Development (the repository's own machinery). What a version number promises is written in `docs/policies/release_policy.md`.

## [Unreleased]

md2html installs with one command on macOS and Linux. md2html itself is the same as 0.8.0: its pages, its command line and its warnings are unchanged.

### Added

- An installer for macOS and Linux: `curl -fsSL https://github.com/githubrobbi/md2html/releases/latest/download/install.sh | sh` picks the release's binary for the system (Apple silicon, also from a Rosetta shell; Intel; Linux x64), downloads it with `curl` or `wget`, refuses it unless its SHA-256 is the one the release's `SHA256SUMS` lists, checks that it runs, and puts it in `~/.local/bin` without `sudo`, replacing the one before it; it says when that folder is not on `PATH`, or when another `md2html` comes first. `MD2HTML_VERSION` installs a chosen release and `MD2HTML_INSTALL_DIR` another folder; Linux on ARM and Windows are told where to go instead. Every release attaches it (`packaging/install/install.sh`), listed and attested like its other assets, and its notes and the README give the command. `scripts/release/test_install.sh` (gate `gate-tests`) runs it under `/bin/sh` and dash against stand-ins for the system and the downloads.

### Development

- A release's page opens with its downloads: a table with one link per archive, then the one-command installs (Homebrew and winget when their lanes are on, building from the source), then the changelog's summary with every change folded under it, and the checksums, provenance, SBOM and build folded last; GitHub's generated list of pull requests is no longer appended, as the changelog says it. `scripts/release/release_notes.py` writes the notes, for `release.yml` and for rewriting an existing release's page (0.8.0's was rewritten so); `scripts/release/test_release_notes.sh` holds its order and its lanes. The README's install section starts with the release's downloads and Homebrew; building from the source follows.
- The Homebrew formula passes Homebrew's own `brew style` and `brew audit --strict --online`: its Linux URL sits under `on_intel` (Linux on ARM, for which no binary is built, is refused instead of given the x64 one), its licence is written as Homebrew asks, its version is read from the URLs, and its header no longer calls the published formula a template. `brew-publish.yml` refuses a rendered formula that still holds a placeholder or that Homebrew's `brew style` or strict online `brew audit` refuses, both run on it as a formula of a temporary tap (a loose `.rb` file is held to Homebrew's rules for its own Ruby instead). Checked by installing 0.8.0 from a local tap: `brew test` passes.
- The winget manifests are written in schema 1.28.0, the one winget-pkgs asks for now (they were 1.12.0, the schema of `SkyLLC.UFFS`'s first version); the first submission, `SkyLLC.md2html` 0.8.0, used them (microsoft/winget-pkgs#489525).

## [0.8.0] - 2026-11-25

md2html renders more of what it is given correctly, refuses more of what it should not do, and says what it used to hide. Nothing was removed from the command line. Some runs that used to end quietly now end with the code that says why (a folder under an input that cannot be read: 66, before any page is made; standard input written over a Markdown file: 64; two inputs that would make one page: 64; `--serve` on a folder it cannot resolve: 66), and `--check` reports new warnings (an unusable `SOURCE_DATE_EPOCH` or `MD2HTML_GLOSSARY_URL`, an unreadable shared glossary, the author's tags md2html had to balance or leave out, a front matter setting given twice, an image `--embed` cannot read because it is not a file, a book `--serve` does not make). The pages of ordinary documents are byte for byte the same, apart from the fixes below and their headings' anchors, which are GitHub's now (under Changed: a breaking change).

### Security

Ways around the guarantees of `SECURITY.md`, each closed.

- A page made with the shared glossary linked to the shared page's own file (`file:///Users/<name>/.config/md2html/glossary.html`), so every page published from it showed the home folder's path and the user's name, and led its readers nowhere. A page links to the full glossary only where `MD2HTML_GLOSSARY_URL` says; without it there is no such link.
- A document could read files from the folder md2html runs in as well as from its own: rendered from the home folder, a document someone sent could put `../Pictures/passport.png` inside its page (`--embed`), its EPUB or its PDF, or any `.css`, `.html` or `.md` under the home folder into its page as a stylesheet, a head file or a translation's original; read from standard input, it read stylesheets and head files from the run's folder, and images beside the page `-o` names when they lay in that folder. A document now reads only from its own folder and below, and from standard input nothing at all. A file refused is a warning that names `--root`. This is a breaking change for anyone whose documents name files above their folder and who relied on running md2html from a folder that holds them: add `--root .` to that command line (or `--root <folder>`) to read from there again; `--root .` reads from where md2html read before.
- The EPUB packed a `data:` image by the type it named, whatever its bytes (`data:image/png,NOT-A-PNG` became `images/img-1.png`); it is packed only when its bytes are that image, as a file is.
- A PDF carried images from anywhere on the disk: Chrome printed the page as written, and a `file:` page loads any `file:` image, so `![x](/home/someone/photo.png)` in a document asking for its PDF put the photo in it. Chrome prints a copy of the page made for printing, its images put inside it from the document's folder and a policy that lets it load nothing else.
- A text file whose name says image and whose text starts with `BM` was taken for a bitmap and embedded or packed; a bitmap is known by its reserved bytes too.
- A link reference with a long destination, used many times, made a page many times its text (a 1 MB destination used 300 times: a 300 MB page, 921 MB of memory). The uses of a text's references copy no more in all than the text holds (100 KB at least, as `cmark` allows); a use past that stays text.
- A diagram could cost far more than its text: a flowchart's edges were not limited, and each edge across many ranks adds a waypoint per rank (51 KB of edges across a 400-node chain took 21 seconds, 576 MB of memory and made 59 MB of page), and a sequence diagram's participants were not (160,000 participants: 8 seconds). A flowchart is drawn up to 1,000 edges and 4,000 waypoints in all, a sequence diagram up to 100 participants; beyond, it is shown as code with a warning.
- Many different warnings took time growing with the square of their number (160,000 footnote definitions no text refers to: 12 seconds); each warning is told once by a set, and the time grows with their number.
- `--serve` answered any page that asked: a page of another site, or of another port of this machine, could load a script of the served folder (`<script src="http://127.0.0.1:8000/config.js">`) and read what it holds. Every answer now says `Cross-Origin-Resource-Policy: same-origin`. It also read a whole file into memory to send it (three requests for a 1 GB file held 3 GB); a file is sent as it is read.
- With `--html` (or `html: true`), an HTML element written to close itself inside an SVG drawing (`<svg><b class="x"/>`, or after a `<p>` there) stayed open in the browser over the rest of the page: the balancing took it for a shape of the drawing, while the browser leaves a drawing at an HTML tag. The rest of the article, the foot and the search dialog could be taken into a link or a hidden `div` of the author's. The balancing now leaves a drawing or a formula where the browser does, and writes such an element empty.
- A document could read files from outside its folder in three ways. An image was embedded, or packed into the book, from the page's own folder as well as the document's, so `-o ~/page.html` let a document embed any image under the home folder; it is read from the document's folder only. A translation's original found by the file name (`notes.md` for `notes.de.md`) was read without the folder check, so a `notes.md` linking out of the folder put the outside file's language into the page; it is checked as `translated_from` is. And a stylesheet, a head file or an image was checked on its resolved path but read through the path as written, so a link swapped in between led the read elsewhere; what is read is the path the check resolved.
- A stylesheet named thousands of times in the front matter was read into the page each time (4,000 mentions of a 100 KB file made a 400 MB page); each file is read once.
- A PDF a document asked for (`pdf: true`) was printed by Chrome to a hidden name beside it, and Chrome follows a link there: a link planted at `.report.pdf.md2html-tmp` (in a repository, say) made it overwrite any file the person running md2html may write. Chrome prints into a hidden folder md2html makes new, after removing whatever was at its name.
- A Markdown text named `book.epub` whose front matter asks for its book was overwritten by it, and one named `notes.pdf` asking for its PDF the same: only the page was checked against the input. The book and the PDF are judged as the page is, and the run ends with 64.
- With `--html` (or `html: true` in the front matter), an attribute behind a namespace prefix the author declared (`<svg xmlns:x="http://www.w3.org/1999/xlink"><a x:href="javascript:...">`) kept a script URL in the EPUB, whose XML reader takes `x:href` for a link; the HTML page did not run it. The filter keeps a prefixed name only when it is one of `xlink:href` (checked as a URL), `xlink:title`, `xml:lang` and `xml:space`, refuses `xmlns` and `xmlns:*`, and the book declares XLink's namespace itself when it is used.
- A file named `javascript:alert(1).md` (Linux and macOS allow `:` in a name) was linked by `--nav`, the language switch, its alternates and the page's own download as `javascript:alert(1).html`, a script URL that ran when clicked; a folder of that name in `translated_from` did the same. A link made from a name escapes its `:` now (`javascript%3Aalert(1).html`), with every other character a URL would read otherwise (under Fixed).
- A document could give its page a script: front matter `mermaid_js: x.js` put a `.js` file from its folder into the page, and `--csp` hashed it among the page's own scripts. mermaid.js is named only on the command line now (`--mermaid-js`); `mermaid_js` in the front matter is refused with a warning (`docs/command-line.md`).
- A stylesheet could end the page's `style` element with `</STYLE>` (or any spelling but `</style>`) and put a script or a meta refresh after it, from a file a document names (`css:`) or the command line; the meta refresh worked even with `--csp`. A stylesheet or a script inside the page has its end tag broken whatever the case of its letters.
- `--fragment --html` wrote an HTML block of the Markdown as written, so a `<script>` in one reached the fragment; the page with `--html` and inline tags in the fragment were cleaned, an HTML block in the fragment was not. It goes through the same filter as the page's now, and the test that no document puts running code in its page checks the fragment too.
- The author's raw HTML could break the page around the article. A `</div>` the author never opened closed an element of md2html's page (and with `--html`, a `</main>` or `</article>` closed its landmarks); a `<div>` or `<details>` left open took in the notes, the glossary and the foot. The author's tags are balanced now, by default and with `--html`, in the page, the fragment and the book: an element is closed inside the element of md2html's it was opened in (the article, a list item, a quote, a callout, a footnote, a paragraph, a heading, a table cell, emphasis, a link), an end tag that closes nothing open there is left out, and an end tag closes what was opened after its element, so `<div><p></div></p>` nests. A start tag ends what HTML lets an author leave open (a paragraph before a block, a list item before the next, a table cell before the next), `<div/>` is an empty `div`, and void elements open nothing. `<details>` in one HTML block and `</details>` in a later one still hold the Markdown between them. md2html says what it changed: an end tag it left out and an element it had to close, each at its line. Pages whose HTML balances are byte for byte the same.
- `</scripts>` no longer ends a `<script>` element that the sanitizer drops, and `-MOZ-BINDING` is refused in a head file's style like `-moz-binding`.
- A page read from standard input could be written over a Markdown file (`printf '# x' | md2html - -o notes.md` replaced `notes.md` with HTML and ended with 0). md2html refuses a Markdown output whatever the input, and the run ends with 64.
- A document that named a named pipe stalled md2html for ever: a stylesheet, a head, a translation's original or an EPUB image that is a FIFO was opened, and opening one waits for a writer. A file a document names is read only when it is a file; a pipe, a device or a folder is a warning ("it is not a file"). What the command line names may still be a pipe (`md2html <(...)`).
- The EPUB read its images whole and by name only (40 MB of zeros named `big.png` went into the book). It reads them as `--embed` does: through `--max-embed`, and only when their bytes are an image, of the kind the bytes say.
- A file read by md2html is read through its size limit whatever its size claims, so a named pipe, or a `.md` link to an endless device in a folder md2html walks, is refused instead of read without end. The pages are written through a temporary file created new, so a link planted under its name is not followed.
- An image address whose percent escapes decode to bytes that are not UTF-8 names no file; before, it could name a different file whose name held U+FFFD.
- On Windows: a document could make the EPUB pack a file from outside its folder (`/secret.png` and `C:secret.png` are not absolute there, so they were read from the drive's root or its current folder), and `--serve` served a hidden file asked for with a backslash (`/notes%5C.git%5Cconfig`). Both are judged now on the path's parts as Windows reads them and on where the path leads: an EPUB image, like an embedded one, only from the page's folders, links followed; and the server serves no hidden file, whatever leads to it (on every system, a visible link to a hidden file is not served any more, nor packed an image that links out of the folder). A path ending in a separator names a folder on every system, by md2html's rule rather than the file system's: Windows opens `pic.png/` as `pic.png`, so the server, the EPUB and `--embed` refuse it as a file everywhere; and the server serves a file only under its own names, not with an empty or a `.` part (`//pic.png`, `a/./pic.png`).
- Text built to make the parser slow no longer does. Thousands of nested `[` that never close, unmatched backtick runs of many lengths and long runs of `<a ` took seconds each; each is now read once. A link label longer than 999 characters is no label, as the CommonMark specification says, for link and footnote definitions alike.
- A page with many links to anchors it does not have took time growing with the square of their number (64,000 such links: 54 billion instructions); it now grows with the number (1.9 billion), and each anchor is still reported once, in order.
- A non-breaking space (or any white space longer than one byte) before an attribute in an HTML code block stopped md2html with a crash; the attribute is now coloured like any other.
- An unclosed `<` at the very end of a page's text stopped the EPUB export with a crash; it is now written as text.
- `--serve` answers at most 64 connections at once, gives a request ten seconds to arrive, and ends a reload stream after ten minutes (the page reconnects by itself); `--watch` and `--serve` stop when every input is gone. The server's guarantees (local names only, nothing outside the folder, GET and HEAD only) have tests now.
- `--serve` reads a request by the rules of HTTP/1.1 and refuses what it cannot read with the status that says why. A malformed request line was answered 403, 404, 405 or even 200 (`GET /a.html HTTP/1.1 junk` served the page); it is 400 now, as are a request without a `Host` or with two, a space before a header's colon and a header that is not one. A request line over 8 KiB is 414 instead of being cut and its cut part served, a header over 8 KiB or more than 64 headers 431 instead of being read on or ignored, a request that stops coming 408 instead of no answer, an HTTP other than 1 505. A header that is not UTF-8 no longer drops the connection: only the `Host` has to be text. A refusal reaches the browser even when it sent more than was read (a POST with a body was answered with a reset). Requests from a browser are answered as before.

- The author's start tags could still end md2html's own elements: the balancing knew what the author had opened, not which element of md2html's each piece of text stands in, so a tag at which HTML's parser ends an element passed. `Text <div>x</div> more` in a paragraph, `- a <li>b` in a list item, `| a <tr> b |` in a table cell, and with `--html` an `<a>` in md2html's link or an `<h4>` in its heading: the browser ended md2html's element there and the rest fell outside it. md2html's own markup inside the author's open `<svg>` or `<table>` was moved out of it by the browser, which let a later `<div>` end the paragraph, and inside the author's link md2html's link or footnote number ended the author's link and md2html's own `<sup>` or `<em>` with it. No script ran. The balancing now holds md2html's elements beside the author's, as the browser does, and judges each start tag by HTML's rules for what it ends: one that would end an element of md2html's (or one the author opened outside it) is left out with its end tag, its contents kept, and `--check` names it; a table's part outside any table is left out as the browser drops it. Before writing an element of its own, md2html closes the author's open drawing or table outside a cell, ends the author's paragraph before its block, and makes no link inside the author's link. `tests/browser/nesting.js` reads the article in Chrome and holds every element where md2html's tags put it (under Development).
- Memory grew with a text's lines, not its bytes: 16 MB of one-letter lines took 6.3 GB (780 bytes a line), so the 64 MB input limit did not bound memory. Each line was two inline tokens held in three collections at once, a node was 200 bytes, every line of the block reader owned a copy of its text and every quote or list around it a copy of the copy. A line's end is now part of the text around it, a node is 32 bytes, a block 40 with no spare room kept in a container, and a line, and what a container leaves of it, borrows the text: the same 16 MB take 680 MB, one million such lines 90 MB instead of 792, quotes nested 60 deep half what they took, lists nested 30 deep on every line 171 MB instead of 446 for 1.9 MB. The block reader no longer keeps a record of every line (48 bytes, blank lines included): it reads a line from the text when it needs one, and a quote, a list item or a footnote takes its lines as they come, holding a list item's blank lines as a count until more of the item follows them. 16 MB of one-letter lines take 181 MB (690 MB with the record), 16 MB of blank lines 37 MB instead of 805, quotes nested 30 deep on every line 8 MB instead of 91 for 1.9 MB; the 64 MB limit bounds memory at about 11 bytes a byte of such text. The pages are byte for byte the same.
- md2html refused to write a page over a Markdown file named `.md`, `.markdown`, `.mdown` or `.mkd` only: `-o notes.mdx`, `notes.qmd`, `notes.Rmd` or `notes.mkdn` was written over. One list of Markdown's extensions, its dialects' among them (`.mdx`, `.qmd`, `.rmd`, `.livemd`, `.mkdn`, `.mdwn`, `.mkdown`, `.mdtext`, `.mdtxt`), now decides everywhere md2html tells Markdown by its name: the outputs it refuses, the files of a folder, a link sent to its page, a translation's original, the server's media type.

### Added

- Handbooks. A folder named on the command line whose start page links its pages is one handbook, with no option: its start page is its `SUMMARY.md` (mdBook's), else its `README.md` (the page GitHub shows for the folder), else its `index.md`, and its order is that page's links in the order they stand, each page placed by its first link (a link in code, to the web or out of the folder is passed over). A link to a subfolder's `README.md` opens a part, whose own links follow it a step in; in `SUMMARY.md` a nested item is a step in, a heading names the part after it, and `SUMMARY.md` is no chapter. Every chapter links the chapters before and after it in that order and shows the handbook's contents at the head of its outline, itself marked and its own sections under it; `--serve` and `--watch` do the same. A page of a folder the links enter that no start page links comes after the others with a warning (`not linked from README.md; ...`), which `orphan: true` in its front matter silences; a folder no link enters (`docs/dev`) stays out, its pages plain, with one note. Each language of the translations is a handbook of its own, by its own `README.de.md` or else page for page in the original's order. `--no-handbook`, or `handbook: no` on the start page, renders the folder page by page. A single file, files named one by one without `--nav`, and a folder without a start page that links its pages render byte for byte as before (`docs/command-line.md`, "Handbooks").
- A handbook's images: every chapter may embed, pack and print an image from anywhere in the handbook's folder (the folder the command line named), so chapters in subfolders share one `images/`. Images only: a chapter's stylesheets and heads stay in its own folder, and the folder md2html runs in is not one for being that (`md2html .`; `--root .` allows it). An image a chapter shows from outside the handbook's folder and `--root` is a warning on every run, as it is not put inside a page or a book (`SECURITY.md`, guarantee 2, says so).
- A handbook's glossary: the page at its top named `glossary` (or else the chapter titled Glossary) lends every chapter its terms, each mention explained in place and its entry leading to the glossary page, its meanings' links written from the chapter's folder. A page's own term wins over the handbook's, the handbook's over the personal shared glossary's, which still joins; `--no-personal-glossary` (or `personal_glossary: no`) leaves the personal one out for pages that come out the same on any computer.
- md2html's own documentation is a handbook: `docs/README.md` is its start page, with the reading order, and the README has a chapter on handbooks (10): the layout, the one command, what md2html does with each part and what it costs.

- `--check`, and every run of several pages, finds a link to another page's heading that is not there: a link to `guide.md#setup`, where `guide.md` is one of the run's pages and has no anchor `setup`, is told at its line (`first.md:5: a link points at guide.md#setup, which is nowhere on guide.md`) once every page is made; it landed at the page's top without a word. A page outside the run is not read for it. A new warning: a document `--check` passed may fail it.
- A glossary file, as a handbook written for GitHub has one, is a glossary: a document titled `# Glossary` (or the word for it in any of md2html's languages) is a glossary as a whole, its tables and bold-lead entries terms wherever they stand, so `MD2HTML_GLOSSARY=manual/glossary.md` lends its terms to every page of the manual. Its own page shows each entry where it is written, at its term's anchor (`<tr id="g-cluster">`, where every mention of the term links), its term not linked to itself, and lists no copy at its foot. A glossary table's meaning is the column headed for it (`Meaning`, `Definition`, `Description`, or their words in the seventeen languages: `Bedeutung`, `Signification`, `意味`, `הגדרה`...), else the second column as before. A meaning's link to a Markdown page leads to the page md2html makes of it (`concepts.md#x` is `concepts.html#x`) wherever the meaning is shown, at a page's foot and in its hover, as a link of the page's own text does.
- A diagram md2html draws enlarges over the page as a picture does: a click lifts it to the size of the window, two more bring it closer, it follows the pointer or a finger, and the next click, the cross or Escape puts it back, with the focus where it was. The enlargement is the drawing itself, not an image of it: it stays sharp at every step and keeps the page's colours, in either theme and when the theme changes while it is open. The keyboard reaches it by a button the page's script puts before the drawing, seen when it has the focus and named in the page's language ("Enlarge the diagram", in all seventeen); a page read without scripts, a fragment and a book have no such button and are as before.
- A diagram's title is its caption. A title given in the diagram's front matter (`title:` between two `---` lines at the top of the ` ```mermaid ` block, Mermaid's way for every kind) or by a sequence diagram's `title` line is shown under the drawing md2html makes, styled as a picture's caption, in the page and in the EPUB, and under the enlargement; it names the drawing for readers who cannot see it, unless the author's `accTitle` does. A diagram with front matter used to be shown as code (with `--mermaid-js`, left to mermaid.js); it is drawn now. Left to mermaid.js, a diagram keeps its front matter, and mermaid.js draws the title itself. A diagram without a title is drawn as before.
- `--root <folder>` lets every document of a run read files (stylesheets, head files, a translation's original, images to embed, pack or print) from that folder and below, besides its own folder: a repository's root, so that a page in a subfolder can show `../assets/logo.png`. Only the command line gives one; `root` in the front matter or `--set` is refused, so a document cannot widen what it reads. It applies to `--watch`, `--serve`, `--epub` and `--pdf` alike; a path that is not a folder ends the run with 64. With it, an EPUB image may climb out of the document's folder with `..` into the root, as an embedded one may.
- What the command line promises is written on one page, `docs/command-line.md`: the inputs and where the pages go, every option with its aliases (`--output`, `--self-contained` and `--unsafe-html` among them, which the help does not show), every front matter setting with its other spellings and the keys md2html passes over, the exit codes and when each is given, the environment variables, which stream carries what, and what is stable. A test holds the page and the code to each other both ways, so an option, a setting, an exit code or an environment variable cannot be added to one without the other.
- What a version number promises is written down, in `docs/policies/release_policy.md`: a patch release fixes and adds, but never a warning, and before 1.0 a release that adds a warning, or removes or changes anything of the command line's contract (an option, a setting, an exit code, an environment variable, where a file goes, which stream carries what), raises the minor number; the minimum Rust (1.85, the first with the 2024 edition), what it promises and when it may rise; and the release checklist. `docs/command-line.md`'s "What is stable" points there, and no longer says that the same inputs always give the same bytes: a page shows the day it was made and an EPUB the second it was written, unless `SOURCE_DATE_EPOCH` is set.
- A heading's anchor is promised: the same heading text gives the same id in every version, so a link to `page.html#installation` keeps working (`docs/command-line.md`, "What is stable"). A test holds the rule with a table of heading texts and their ids, from punctuation, letters beyond ASCII, emphasis, code and links to an explicit `{#id}`, repeated headings and the ids the page keeps for itself; changing the rule is a breaking change. The rule is GitHub's (under Changed), each row of the table checked against GitHub's own renderer.

### Changed

- **Breaking:** a folder whose start page links its pages renders as a handbook (above): its pages show the contents and link their neighbours in the start page's order, a page no link places is a warning, so `--check` of such a folder can end with 1 where it ended with 0, and an image a chapter shows from outside the handbook's folder is a warning. `--no-handbook` renders the folder as before.
- `--nav` lists the run's pages in each page's outline too, as a handbook's contents, and leaves a handbook's chapters to their handbook; with `--no-handbook` it links the pages in the run's order as before. `--serve` links them as a run does; it linked none before.
- `--no-glossary` (and `glossary: no`) leaves out every glossary from outside the page: its handbook's as well as the personal shared one.

- **Breaking:** a heading's anchor is the one GitHub gives it, so a link written for the Markdown on GitHub (`concepts.md#1--size-vs-size-on-disk`, `#the-watchdog--surviving-crashes-and-installers`) lands on its heading in md2html's page; it missed before, and the page opened at its top. The anchor keeps what GitHub keeps: no run of characters collapses into one hyphen (`C++ & Rust` is `c--rust`, `1 · Size` is `1--size`), punctuation is left out instead of becoming a hyphen (`What's new?` is `whats-new`, `Version 1.2.3` is `version-123`), `_` and a hyphen at either end stay, an image's description is no part of it, and a repeated heading is numbered `-1`, `-2` (it was `-2`, `-3`), as GitHub numbers it; md2html's own repeated ids (a second code block's address in a section) are numbered the same way. - Faster: a page whose glossary is large renders many times faster, and its time grows with its text instead of with the text times the glossary: a text is searched only for the terms it names. The pages are byte for byte the same.

## [0.7.0] - 2026-11-22

Hardening: md2html cannot be used to make a page that does harm, and no input can stall or crash it. [SECURITY.md](SECURITY.md) states the guarantees.

### Security

- `--html` no longer passes raw HTML as is. Rich HTML (images, links, video, audio, SVG, MathML, tables, layout) passes an allowlist; scripts, event handlers, `javascript:` URLs, frames, plug-ins, forms, `<meta>`, `<base>` and styles that fetch or run anything are removed, the dangerous elements with their contents, and ids the page's own script uses are not taken. **Pages that relied on `--html` to carry scripts lose them**, by design.
- The author's `head` file keeps only `meta` (without `http-equiv`), `link` (stylesheets, icons and the like) and `style`.
- `brand_link` refuses a `javascript:` or `data:` address.
- Files the front matter names (`css`, `head`, `mermaid_js`, `translated_from`) must lie inside the document's folder and be of their kind; the command line may still name any file.
- An embedded image must lie in the document's folder or the folder md2html runs in, and its bytes must be an image (PNG, JPEG, GIF, WebP, AVIF, ICO, BMP or SVG), whatever its name says: a document cannot pull a secret into its page.
- `--pdf` prints with every network connection refused.
- GitHub private vulnerability reporting is on.

### Robustness

- A run of 100,000 asterisks overflowed the stack and aborted; emphasis, links and images now nest at most 64 deep.
- The emphasis pass, the bracket matcher and the reading of link definitions were quadratic: 25,000 `*a*` in one paragraph took 26 s, 50,000 took 112 s, 80,000 link definitions 1.5 s. All are linear now (100,000 `*a*`: 0.2 s; 80,000 definitions: 0.15 s), as CommonMark's reference implementations do it.
- A Markdown file over 64 MB and an image over 32 MB to embed are refused with a clear message; `--max-input MB` and `--max-embed MB` raise them, on the command line only.
- The test suite renders pathological inputs under a time limit on every change.

### The bar

- Saving has its own button, a download arrow at the end of the bar, with its own menu (the page, print or PDF, the PDF and the EPUB); **Aa** holds the text size and the theme only.

### Live pages

- `--serve [--port n]` serves the pages on this computer and reloads every open page the moment its Markdown is saved: loopback only, this machine's names only (no DNS rebinding), the document's folder only, GET and HEAD only.
- `--live` (`live: true`, or `live: 30` for a time in seconds; `--ttl`) gives a page its own time to live: on a server it then fetches the first kilobyte of itself and reloads if its fingerprint changed; opened from a file it simply reloads. Every page now carries that fingerprint (`<meta name="md2html-page">`). With `--csp`, a live page may connect to its own origin only.
- A reload keeps the reader's place, best effort: the block at the top of the screen by its text in its section, then anywhere, then the closest text or position in the section; else the section before; else the top. It waits while the reader is selecting or has a menu, search or a figure open, and says "Updated" afterwards (in the page's language).

### Sharing

- The **#** beside a heading copies the section's link and says so ("Link copied", read aloud too); on a phone it opens the system's share sheet.
- Selecting words offers a link to exactly that passage, a text fragment (`#:~:text=`) that opens the page there, highlighted.

## 0.4.0 - 2026-11-21

A full Markdown reader under the same page.

### Reads all of Markdown

- A new parser, standard library only, built the way CommonMark specifies: blocks as nested containers, inline emphasis and links from a delimiter stack. It passes 640 of the 652 examples of CommonMark 0.31.2, and the tests keep that count from falling.
- Nested lists, quotations (and quotes inside quotes), indented code, `~~~` fences, setext headings, reference links, autolinks, hard line breaks, backslash escapes and entities.
- GitHub's additions: task lists, strikethrough, bare URLs, footnotes, table column alignment, and the five alerts `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`.
- `***bold italic***`, images inside a sentence, parentheses inside a URL, and `[V]`-style brackets as plain text: the gaps the README listed are closed.
- Maths: `$...$`, `$$...$$` and ` ```math ` typeset as MathML, which every current browser draws without a script. Dollar amounts stay dollar amounts.
- Code coloured for some twenty languages and formats, with no grammar engine.
- Harmless HTML passes (`<kbd>`, `<sub>`, `<details>`, `<br>` ...); anything else is shown as text unless `--html` trusts it.
- `{width=50%}` after an image sizes it; `{#id}` after a heading names its anchor.

### Settings

- Front matter at the top of the Markdown, and the same keys on the command line (`--set key=value`, `--title`, `--lang`, `--brand`, `--footer`, `--css`, `--head`): title, language, brand and its link, kicker, eyebrow, date, version, description, author, footer, extra stylesheet and head.
- `lang: de` puts the page's own words in German: search, glossary, callouts, footnotes, figure, theme and text-size controls, and the date.
- Meta description (from the lead by default), Open Graph title and description, theme colours for both themes, an icon, a generator tag. `index: true` lifts the default `noindex`.

### The command line

- Several files or a whole folder per run, `-o` for a page or a folder, `-` for stdin and stdout.
- `--check` writes nothing and lists what to fix, with the line: anchors that are not on the page, missing files, footnotes without notes, raw HTML shown as text, unknown settings. It exits 1 when there is anything.
- `--watch` renders again on every save. `--nav` links the pages of one run with previous and next. `--fragment` writes only the HTML of the Markdown.
- `--embed` puts the images inside the page. `--csp` adds a Content-Security-Policy that lets only the page's own scripts and styles run.
- A link to a Markdown file beside the page goes to its HTML twin. Pages are written whole or not at all.

### The page

- Footnotes explain themselves on hover, like glossary words, and lead back to where you were.
- The words a search found are lit where it lands; the search is announced to screen readers and works as a combobox.
- A real print stylesheet: controls gone, link addresses printed, nothing cut across a page.
- Escape takes a word's explanation away; wide tables and code take the keyboard's focus; high-contrast mode is respected; the article is the page's main landmark.
- A page without chapters gets no empty outline; a document without a `# Title` gets one from its file name; several `#` headings become chapters.

### Accessible

- An audit with axe-core (WCAG 2.0 to 2.2, A and AA, and best practice) finds nothing on the README, the showcase, the docenta handbook, and the plan, research and family pages built on this machine, in both themes and at phone width.
- Every colour meets 4.5:1: code comments, numbers, strings and removed lines, and the tip's label, were darker than they looked.
- Links in running text are underlined, so colour is not the only sign of them.
- Callouts are notes inside the article, not landmarks of their own; the bar is the page's banner; the search button keeps its name on a phone; a task's box says whether it is done; each wide table's region has a name of its own; an empty header cell is a plain cell.
- Long words and bare URLs break instead of pushing the page sideways on a phone.
- Escape always closes the search, however it was opened.
- The outline's drawer slid for 1.4 s (it borrowed the landing glow's time); it takes 0.18 s, and print never catches it half-way.
- A click-through in Chrome (`tests/browser`) and the audit run in CI.

### Fixed

- A page with many bare brackets could make the renderer grow without bound (one run reached 38 GB). Rendering is now linear: the 261 KB docenta handbook takes 0.07 s, where it took over two minutes.
- `javascript:` and `data:` links were written into the page. They are now removed, however they are spelled.
- Code spans that held a `<` or crossed a line were split apart; bold runs could invert after a callout's label.
- The glossary's outline entry appeared on pages without a glossary; the search said "the book" on every page.

### Changed

- A quotation without a callout word is a quotation now, not a note. One that opens with a bold lead (`> **For Esther.** ...`) is still boxed as a note.
- The glossary is titled "Words used here", and the search says "Nothing on this page matches that."
- Anchors keep letters beyond ASCII (`über-die-lage`, not `ber-die-lage`).
- The docenta-specific glossary aliases are gone; a glossary's `Also` column names other spellings for any page.
