# GOTO.md: where md2html stands, what's next, which switch does what

The **living state doc** for this project. `AGENTS.md` holds the rules and `docs/forge/GETTING-STARTED.md` the how-to; this file holds the *state*: where the project stands, the rhythm for daily work, how the code is held to the lint table, and the runbook for every dormant capability.

**Maintenance rule:** this file is a snapshot, not eternal truth. When a checkbox flips, a lane goes live, or the plan changes, update it **in the same PR**. A stale GOTO.md is worse than none.

---

## 1. Where we are (snapshot: 2026-11-24)

### The product

md2html 0.7.7: Markdown to one self-contained HTML page (`docs/capabilities.md` is the tour, in seventeen languages). One crate, `crates/md2html`, no dependencies, unsafe code forbidden. All 652 CommonMark examples pass; that number is a floor. Its twenty-one modules stand in nine layers, each using only its own or lower ones and none in a circle (`docs/ARCHITECTURE.md`); a test holds it. Every item is visible only as far as the code that uses it (private, its parent module, or the crate), and each module's root file is the one place the rest uses it through (its submodules are private; the layer test holds that too). A struct shows its fields only when it is a record; a value with a rule keeps them private behind its methods (`docs/policies/type_policy.md`). Markup is `text::Html`, apart from plain text, so nothing is escaped twice or not at all (a test finds every entry into the page escaped once); a setting with a rule is read once into its type, a heading's level is one to six, and a boolean that picked a way of working is an enum that names it. What the command line promises (options, settings, exit codes, environment variables, what is stable) is `docs/command-line.md`, and a test holds the page and the code to each other; what a version number promises for it, the minimum Rust and when it may rise and the release checklist are `docs/policies/release_policy.md`. A failure is seen, never turned into a quiet default: a folder that cannot be read stops the run, a file that is there but cannot be read is named as such, a setting or variable that cannot be used is a warning; a decision about a file name is made on the name as the file system has it, and a link never names a file under U+FFFD (`docs/policies/panic_policy.md`, hostile-input rule 6). The error strategy is by kind of crate: messages and exit codes in md2html, `anyhow` with context in the tooling binaries, typed errors in the two libraries. Traits and generics do work or are not there: md2html has two traits, each with its reason written down, the tooling none, `dyn` only where the standard library puts it, a sorted type has a total order and a default is a real value (`docs/policies/type_policy.md`). Speed is measured, not guessed: `just measure` times the stages of a render on the repository's documents and on a handbook with a glossary of 2000 terms, and a change made for speed or memory names the numbers it moved (`docs/policies/allocation_policy.md`). A page's time grows in proportion to its text, its glossary and its links included: a text is searched only for the terms it names, and its memory with its bytes, not its lines (the block reader reads a line from the text when it needs one and holds a few a level of nesting, a list item's blank lines as a count; a line borrows the text, a line's end is part of the text around it, a node is 32 bytes); tests hold such bounds by size (`docs/policies/hostile_input_policy.md`). The one threaded part, `--serve`, fits on a page (`docs/policies/concurrency_policy.md`): every thread has an owner that waits for it and a defined end, the server stops with nothing left running, the shared state is one `Site` without `Arc` or atomics, and a request is read by HTTP/1.1's rules or refused with the status that says why (400, 408, 414, 431, 505); tests over real connections hold the limits and the stop. Every child process the release pipeline starts has a time limit. Where Linux, macOS and Windows differ, md2html takes the standard library's answer and keeps its own rules in one module (`system`: the home folder, a path as a `file:` URL, a relative path that stays in its folder, standard output written through a handle of its own so that a refused write is seen whatever Rust built md2html), the only one with a `cfg` on an operating system, and a test holds each system's rule on that system, where CI runs it (`docs/policies/platform_policy.md`). How it is tested is one page (`docs/TESTING.md`): each kind of test, what it guards and where it runs. Tests run the built program for the command line's contract; a seeded generator holds every page to its invariants; the differential test is in the repository (`just differential` compares 8,300 documents rendered six ways with another build, byte for byte; `just generated-documents` and a weekly job fail on a crash or a hang); the sanitizer, the text helpers and the inline, block and document modules are mutation-tested weekly with every mutant caught.

### What this repository cannot have, and what stands in

- **No merge queue.** GitHub offers one only to repositories an organization owns; this one belongs to a user account. So the heavy lanes of `pr-fast.yml` (clippy, tests, rustdoc, deny and vet, Windows clippy) run on the pull request itself, and the ruleset requires their aggregate. Moving the repository to an organization would make the queue available; `scripts/ci/main-ruleset.json` would then gain the `merge_queue` rule.

## 2. The rhythm (daily)

```bash
git switch -c feat/<topic>      # never work on main
# edit
just check                      # seconds: compile, format, file size
just lint-ci                    # clippy, as CI runs it
just test                       # nextest suite
just go                         # the definition of done
git add -A && git commit -m "feat: ..."   # hooks run, seconds
git push -u origin feat/<topic>           # gate battery, ~30 s
just pr "feat: ..."             # validated title, opens the PR
just merge <PR-number>          # watches every check, then merges (never raw gh pr merge)
```

- Gate fails? `AGENTS.md` section 6 has a row for every gate (the gate `doc-references` holds it to `scripts/ci/gates.toml`); `docs/forge/GETTING-STARTED.md` the same fixes for a person. Fix the cause, never bypass.
- Conventional Commits, one scope at most; every commit signed; merge commits only.
- Weekly, automatic (Mondays): the tier-2 deep suite (coverage, cargo-careful, Miri on the parsers' and helpers' unit tests, mutation testing of the modules in `scripts/ci/mutants-scope.txt`: the sanitizer, the text helpers, the inline parser, the block reader and the document assembly, every mutant caught), the vet refresh, the nightly-toolchain canary. A failure files an issue.
- Dependabot opens grouped pull requests on Mondays. A patch-level bump merges itself once every required check is green; a cargo bump first needs the audit store to know the new versions (`cargo vet`, then commit `supply-chain/imports.lock` to the PR branch).

**Reading order for a session:** `AGENTS.md` → this file → `docs/capabilities.md` for what the product does. For a person new to the code: `README.md` → `docs/CONTRIBUTING.md` (and `docs/forge/GETTING-STARTED.md` to set the machine up) → `docs/ARCHITECTURE.md` → `docs/policies/` → `docs/TESTING.md`.

## 3. The lint table, held with one exception (since 2026-11-23)

Every Rust file of the workspace, the tooling and the tests included, meets the whole lint table in the root `Cargo.toml` and `clippy.toml`, with no `#[allow]` and no `#[expect]` but the one below. A finding is fixed at its cause, usually the type or the structure it points at (`AGENTS.md`, `docs/policies/lint-posture.md`).

The one exception, decided by the owner on 2026-11-23: `clippy::float_arithmetic` in `crates/md2html/src/mermaid/geom.rs`, the arithmetic of the diagram geometry. Everything else in the diagrams works through its `Len`, `Point`, `Size` and `Rect` types.

`scripts/ci/anti_pattern_gate.sh` (gate `anti-pattern`: every commit, every push, every pull request; its own cases are gate `gate-tests`) refuses any other lint exception in any Rust file, lossy decoding of bytes or names (`from_utf8_lossy`, `from_utf16_lossy`, `to_string_lossy`) in production code, and discarded writes. There is no marker that silences it, no exceptions list for file sizes (every Rust file is under 800 lines), no soft gate and no bypass variable.

How the code got there: on 2026-11-22 the table was switched on over 2,051 findings, recorded as debt. On 2026-11-23 every module was rebuilt so that the findings' causes are gone: a shared reader (`crate::scan`) instead of hand-kept positions into text, the page model as one struct per kind (`model.rs`), typed ids and records instead of parallel vectors, named types instead of tuples and `bool` bundles, long functions as named steps, one way to report output. Every change was checked against a differential test of 8,298 documents in six modes (49,788 renders), which came out byte for byte the same apart from one deliberate fix (a stray comma in two button titles).

## 4. What's next

1. **Wider mutation testing.** The weekly mutation job is required and covers the sanitizer, the text helpers, the inline parser, the block reader and the document assembly, where every mutant is caught. Widen it module by module (`scripts/ci/mutants-scope.txt`), each once its tests catch every mutant: `docs/TESTING.md` has the next modules (`serve`, `render`), their mutant counts, run times and how many are still missed.
2. **The first release** with binaries, when the owner decides: section 5, `lane:release`, and the checklist in `docs/policies/release_policy.md`.
3. **Faster CI, decided and done (2026-11-24).** A pull request's checks spent most of their runner time before any check ran (measured on the runs of PR #47). Three changes cut that setup and leave what is checked the same. `rust-toolchain.toml` names the channel and the minimal profile alone, so a job no longer installs every component and all five targets (20 to 30 seconds in each of thirteen jobs); each job adds what it uses, and `workflow-drift` (property 11) holds every job of every workflow to exactly that, while `just toolchain-ensure` (run by `just setup` and `just go`) gives a developer's machine everything with the pin. `ci.yml`'s supply-chain job installs cargo-deny and cargo-vet from their releases, SHA-256 checked, instead of compiling them (180 seconds). The tooling the gates run, the pipeline and `ci.yml`'s clippy and tests build with the `tooling` profile, release without LTO (4 seconds from clean instead of 12; `docs/policies/build_codegen_policy.md`); md2html's release profile and every build of what ships are unchanged. Clearing disk space (50 to 180 seconds in each of six jobs) is kept, by decision. The pull request that made these changes is the place to read the new setup times from. The tests themselves take 12 to 17 seconds and gain nothing from being split.

## 5. Which switch does what (dormant lanes)

| `lane:release` | GitHub release binaries (archives + SHA256SUMS), from the tag the owner signs | `gh variable set LANE_RELEASE --body true`, then `just ship`, `just merge <PR>` and `just release-tag` | First release. `just release-local` builds the same archives here, for nothing |
| `lane:slsa` | build provenance attestation on release artifacts (no secrets) | `gh variable set LANE_SLSA --body true` | Same moment as `lane:release` |
| `lane:release-plz` | the crates.io publish job, dispatched by `release.yml` for the tag `v<version>` once its release exists; it never bumps a version, writes the changelog or makes a tag (`release-plz.toml`) | `gh variable set LANE_RELEASE_PLZ --body true` (with `lane:crates-publish`) | With `lane:crates-publish` |
| `lane:preview` | real binaries for one PR's commit, with a SHA256 manifest | label the PR `preview-artifacts` (+ `preview-macos`) or dispatch `preview-artifacts.yml` | When someone must try a build before merge |
| `lane:brew` | Homebrew tap formula per release | `LANE_BREW=true`, `HOMEBREW_TAP_TOKEN`, a tap repository | After releases exist |
| `lane:winget` | Windows package manager PRs per release (`SkyLLC.md2html`; the fork synced first, as UFFS does) | the first version submitted by hand (`packaging/winget/README.md`), then `WINGET_TOKEN` (classic, `public_repo` + `workflow`) and `LANE_WINGET=true` | After the first release |
| `lane:crates-publish` | crates.io publishing + weekly dry-run guard | reserve the name, make this repository its trusted publisher on crates.io (no token is stored: the publish job signs in with OIDC), `LANE_CRATES`, `LANE_RELEASE_PLZ` and `ENABLE_CRATES_IO_PUBLISH` = `true` | If md2html is to be `cargo install md2html` |
| `lane:codecov` | coverage upload + PR comments | `CODECOV_TOKEN` secret, `LANE_CODECOV=true` | When coverage numbers are wanted on PRs |
| `lane:codesign` | stable macOS binary identity; for releases: the release waits as a draft, and the owner signs and notarizes the macOS binaries on his Mac and publishes it (`just release-sign-macos vX.Y.Z`); off, releases publish at once with ad-hoc macOS binaries | `just setup-codesign`; for releases `LANE_CODESIGN=true` (with `lane:slsa`), and the Developer ID and notary key in the owner's keychain, no secret on GitHub (`docs/forge/CODE-SIGNING.md`, section 5) | With `lane:release`, for Macs |

Always on: the main guard (`just merge`, the pre-push hook, `main-merge-guard.yml`, the ruleset), CodeQL (the repository is public), the cross-platform lint gates at pre-push.

The release workflow has never run here. It was read against the release checklist on 2026-11-24 and what can run without GitHub was run (`docs/policies/release_policy.md`, the last section, says what only a real run proves). Its SBOM step writes one `sbom-<crate>.cdx.json` for each crate under `crates/` (`sbom-md2html.cdx.json` for the product, `sbom-md2html-version.cdx.json` for the tooling's version helper).
