# Security

md2html turns Markdown, possibly written by someone else, into a page that other people open. It is built so that it cannot be used to make a page that does harm. This page is for the people who render Markdown they did not write, and for anyone who finds a way around it: what md2html guarantees, and how to report a problem.

## What md2html guarantees

1. **A page runs only md2html's own code.** No script, event handler, `javascript:` or `vbscript:` URL, frame, plug-in, form, meta refresh or `<base>` from the Markdown reaches the page, in any mode. Raw HTML is shown as text except a short list of harmless tags; with `--html`, rich HTML (images, links, video, SVG, tables, layout) passes through an allowlist that removes everything executable: an element stands only when it is on the list, an attribute only where HTML defines it (an event handler, `srcdoc`, `formaction` and the others that could run or fetch code not even there), and an address only when it is safe. The author's tags are balanced inside the article, in every mode: whatever they open is closed inside the element of md2html's it was opened in, an end tag that closes nothing the author opened is left out, and so is a start tag at which the browser would end one of md2html's elements (a `<div>` in md2html's paragraph, a `<li>` in its list item, a `<tr>` in its table cell, an `<a>` in its link), so the author's HTML can neither close nor leave open an element of the page around it. The author's `head` file keeps only `meta` (without `http-equiv`), `link` (stylesheets, icons and the like) and `style`, and a stylesheet cannot end its element. A document cannot give the page a script: mermaid.js comes only from the command line (`--mermaid-js`).
2. **A document reads nothing it should not.** Files named in the front matter must lie inside the document's folder, be of their kind (`.css`, `.html`, `.md`), and be files (not a pipe, a device or a folder). An image is embedded, packed into an EPUB or printed into a PDF only from the document's folder, only when it is a file, and only when its bytes are an image. Inside means where the path leads, links followed, is in that folder or below it. The folder md2html runs in is not allowed for being that, so a document someone sent, rendered from the home folder, cannot reach the rest of it; and a document read from standard input, which has no folder, reads no file at all. Only the command line, which the person running md2html controls, may name files elsewhere, or add one folder every document of the run may read from (`--root`); a document cannot add one (`root` in its front matter is refused).
3. **Hostile input cannot stall or crash it.** Parsing is linear in the input; nesting of emphasis, links and images is capped at 64 levels; inputs over 64 MB and images over 32 MB (embedded or packed into an EPUB) are refused (`--max-input`, `--max-embed` raise these on the command line only), and so are the other files a page is made from (stylesheets, heads, mermaid.js, the original of a translation, the shared glossary) over 64 MB. Every file is read through its limit, never by trusting the size the file system reports, so a pipe or a device behind a link cannot make it read without end, and a file a document names is read only when it is a file, so a named pipe cannot make md2html wait for ever. The test suite renders pathological inputs (100,000 asterisks, brackets, quote marks; tens of thousands of footnotes and link definitions) under a time limit on every change.
4. **It writes only where it is told.** It never overwrites its input or writes a Markdown file, and writes each output whole or not at all, through a temporary file it creates new: a link planted under that name is not followed.
5. **The local server stays local.** `--serve` listens on 127.0.0.1 only, answers only requests addressed to this machine's own names and its port (so a web page elsewhere cannot reach it by DNS rebinding; an HTTP/1.0 request without a `Host`, which no browser sends, is answered as a program on this machine asked it), serves only files inside the document's folder (no hidden files, no way out by `..` or its encodings, or by a link), and only to GET and HEAD. Every answer says that only the server's own pages may use it (`Cross-Origin-Resource-Policy: same-origin`), so a page of another site or another port of this machine cannot read the folder's files through a script or an image; a file is sent as it is read, never held whole in memory. It serves at most 64 connections at once and tells the rest it is busy, gives a request 10 seconds to arrive, refuses a request it cannot read whole with the status that says why instead of guessing at it (400 malformed, 408 too slow, 414 a request line over 8 KiB, 431 a header over 8 KiB or more than 64 headers, 505 an HTTP version it does not speak, 503 busy), and ends a page's reload signal after 10 minutes, when the page asks for it again. When it stops, it closes every connection and leaves no thread running.
6. **A live page talks only to where it came from.** `--live` lets a page fetch the first kilobyte of its own URL to see whether it changed; with `--csp` the policy allows exactly that origin and nothing else.
7. **PDF printing is offline.** `--pdf` runs Chrome headless with a fresh, throwaway profile, a time limit, and every network connection refused. It prints a copy of the page made for it, whose images are inside it and whose policy lets it load nothing else, from a folder md2html makes new.
8. **No third-party code.** The binary is the Rust standard library and md2html; the toolchain is pinned, and `cargo deny` and `cargo vet` gate any dependency (see [docs/SUPPLY-CHAIN.md](docs/SUPPLY-CHAIN.md)).

What md2html does not promise: it does not judge what a page *says*. A page can still carry a misleading link to an ordinary web address, as any document can; `--csp` additionally forbids the page's scripts any connection (images and media the text names still load).

## Reporting a problem

Please report a way around any of the guarantees above privately, through GitHub's private vulnerability reporting on this repository (Security, then "Report a vulnerability"), with a Markdown file that shows it. Fixes are released as a new version with a CHANGELOG entry.
