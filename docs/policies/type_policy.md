# Types, traits and generics

For whoever adds a type, a trait or a generic: what a type must say about the data it holds, and when a trait or a generic earns its place.

## The rule

Data gets a type that says what it is, and a state that cannot occur gets no way to be written down. Traits and generics are used where they do work, not for decoration.

## Why

Most lint findings are symptoms of a missing type. A function with nine arguments is a struct nobody named; four booleans are an enum with a few real cases and many impossible ones; a `usize` used as a place in a text has to be checked at every use, where a type that can only hold valid places needs no check at all. Fixing the type removes the whole family of findings at once; fixing each site leaves the cause in place for the next change. This is the main way findings are fixed in this workspace ([lint-posture.md](lint-posture.md), "Fixing a finding").

## Enforced by

`Cargo.toml`, at deny: `too_many_arguments`, `type_complexity`, `struct_excessive_bools`, `fn_params_excessive_bools`, `option_option`, `large_enum_variant`, `wildcard_enum_match_arm`, `rest_pattern_accessible_field`, `wrong_self_convention`, `use_self`, `trait_duplication_in_bounds`, `impl_trait_in_params`, `partial_pub_fields`, `pub_underscore_fields`, `missing_docs_in_private_items`; at warn (an error under `-D warnings`): `multiple_bound_locations`, rustc's `unreachable_pub`. The thresholds are Clippy's defaults: seven arguments, three booleans. Gates `lint-prod`, `lint-tests`, `lint-ci`.

## Types

- **Name what travels together.** A tuple such as `(f64, f64, f64, f64)` or a long parameter list becomes a struct with named fields: a box on a drawing is `Rect { left, top, right, bottom }`, a point `Point { x, y }` (`mermaid/plane.rs`).
- **A quantity has a type.** A length on a drawing is `mermaid::geom::Len`, not a bare `f64`; its arithmetic is written once, in `geom.rs` ([lint-posture.md](lint-posture.md), "The one exception").
- **One enum for one choice.** Booleans of which only some combinations make sense are a choice between cases: name the cases. The command line's are `Action` (write or check) and `Mode` (once, watch, or serve on a port) in `cli/args.rs`, and `Shape` (page or fragment) in `document.rs`, the layer that acts on it. A tag in the EPUB writer is `Opening`, `Closing` or `Empty`, not two booleans of which one combination cannot occur.
- **A boolean is a fact; a way of working is an enum.** A `bool` stays where it answers a yes-or-no question about the thing that holds it (a list item is a task, a column is active, the page has a figure) and a call passes it by a name that says so. Where it picks how something is done, and a call would read `f(x, false)`, it is an enum whose variants say what each way is: `block::Reading` (`CommonMark` or `Author`), `model::Spacing` (a list `Tight` or `Loose`), `text::UrlFor` (a `Link` or an `Image`, the one case a `data:` URL may carry), the server's `Body` (`Sent` or `Withheld`), a sequence diagram's `Figure` (`Participant` or `Actor`).
- **Markup and text are different types.** `text::Html` is HTML: plain text becomes it only through `Html::escape`, and markup md2html wrote only through `Html::markup`. It is written as it is and is not a `&str`, so it cannot be escaped twice, and a `String` cannot stand where markup is expected. What the page says about itself (`page::Meta`) holds its markup as `Html` and its plain text as `String`; a test renders every place text enters the page around the article and finds it escaped exactly once (`src/tests/escaping.rs`). A stylesheet and a script written into the page are `page::Style` and `page::Script`, whose constructors break a closing tag where the element is written.
- **A value with a rule is read once, into its type.** A setting with more to it than words or yes and no is parsed by `Settings::set` into the type that holds its rule (`config/values.rs`: `Diagrams`, `Translations`, `Fingerprint`, `Ttl` held between five seconds and a day), so the front matter and the command line share one reading and a page matches on the value instead of comparing words. A heading's `model::Level` is one to six by construction; a URL checked once and written elsewhere is a `text::SafeUrl`. A warning about the whole page has no line (`Option<NonZeroUsize>`), not line 0.
- **Three states are three variants.** `Option<Option<T>>` becomes an enum: the sanitizer's `Verdict` on an attribute is `Value(String)`, `Bare` or `Drop`.
- **Records, not columns.** Vectors kept in parallel and indexed by the same `usize` become one vector of a record type.
- **A place is not a number.** `scan::Mark` and `scan::Spot` are newtypes over a position: only a reader hands one out, and the reader checks it when it is given back, so no caller does arithmetic on positions or checks them. In the diagrams a node, an edge or an actor is named by its own id type (`EdgeId`, `ActorId`), so the number of a node cannot look up an edge.
- **Keep the invariant inside.** `Scan` holds the text and the unread rest, and the rest is always a tail of the text; nothing outside the module can break that, so nothing outside has to check it.
- **Match every case.** No wildcard arm and no `..` over fields that could be named: when a variant or a field is added, the compiler lists every place that has to decide about it.
- **Visibility says scope.** md2html is a binary: its items are `pub(crate)`, `pub(super)` or private, never `pub`, each as far as the code that uses it and no further. A module's submodules are private, and its root file offers what the rest uses ([ARCHITECTURE.md](../ARCHITECTURE.md); the layer test holds it).
- **A record shows its fields; a value with a rule hides them.** A struct's fields are all public or all private (`partial_pub_fields`). They are public when the struct is a record of named data that callers build and read, whose fields do not constrain one another: the page model (`model.rs`), the settings, the interface's words, a parsed diagram or tag, a point on a drawing, the tooling's mirrors of `gates.toml` and `Cargo.toml`. They are private, behind the methods that keep the rule, when the value has one: a `text::Date` has a day of the month from 1 to 31 because only `civil` and `iso_date` make one; the glossary's `Linker` links a term once a chapter and numbers every mention; a sequence diagram's `Column` opens and closes its activations like brackets; the tooling's `WorkflowState` never holds a step as both completed and failed. A rule about one field's values alone (a heading's level from one to six, a setting that takes one of three words) belongs in that field's type (`Level`, `Diagrams`), not in hiding the record.
- **`#[must_use]` where dropping the value is always a bug.** Clippy's `must_use_candidate` and `return_self_not_must_use` look only at what a crate exports, and md2html exports nothing, so here the attribute is placed by hand: on a call that does work and returns what must not be lost (`render_doc`'s page and warnings, `Reporter::finish`'s exit code, the bar `Column::deactivate` closes, the count `Linker::into_minted` hands over) and on a method that returns a changed copy (`Switches::with`). Those two kinds must carry it. A pure function needs it less, since calling one for nothing is visibly dead code; some carry it bare all the same (`Scan::new`, `Direction::code`), which costs nothing. In the developer tools' library, which exports its items, the lints place it.
- **No `#[non_exhaustive]`, no sealed traits.** Both protect a published crate's users from its next version. md2html publishes nothing, and its only library crates are used by binaries in the same workspace: a new variant should break every `match` that does not handle it (`wildcard_enum_match_arm`), which `#[non_exhaustive]` would prevent, and no crate outside could implement a trait to begin with.
- **Names follow the conventions.** `as_` borrows cheaply, `to_` converts at a cost, `into_` consumes (`wrong_self_convention`). The lint sees the receiver, not the cost: a method that builds a `String` or copies what it is given is `to_` (`Bracket::to_text`) whatever its receiver.
- **A sorted type has an order.** What is sorted or kept in a `BTreeMap` has an `Ord`, derived where its fields have one (the id types, `Level`, `Mark`, `Switch`). A sort key holding a measured number implements `Ord` through `mermaid::geom::compare`, the order `<` gives made total (a NaN after every number): the layout's `Key`, and `Len::compare` for a list of lengths. `partial_cmp(..).unwrap_or(Equal)` is no order: it makes a NaN equal to everything, and `sort_by` may panic on it.
- **A default is a value.** `Default` is derived where the empty value means something: no settings, no switches on, an empty archive, an accumulator with nothing in it. Not to fill a struct update: a tag with no name is not a tag, so the EPUB rewrite's `Tag` names each field where it is made.
- **Every item says what it is.** Private items included (`missing_docs_in_private_items`).

## Traits

A trait earns its place with two or more real implementations, or as the seam a test substitutes. Otherwise a function or an inherent method does the job with less to read. A closed set of kinds is an enum, not `dyn Trait`: the blocks and the inline content of a document are the enums `Block` and `Node` in the page model (`model.rs`). Every kind of block and every compound kind of inline content (a link, an image, a formula) is a struct of its own that its variant carries, so a reader binds the one value it matches, and a match over them names every kind.

md2html declares two traits:

- `text::Put`, implemented for `String`. It exists so that the `put!` macro can append formatted text through one method call whether it is given a `String` or a `&mut String` (a method call adjusts its receiver; a function would need one macro arm for each), and so that it takes only a `String`: a sink that can fail, a `Formatter`, keeps `write!` and its `Result`. That is its seam, and the one reason a trait with one implementation stays.
- `mermaid::table::Id`, implemented by each of the five id types of the diagrams. A `Table<Key, Item>` keeps its entries by an id of one type, so an id of another kind cannot be used to look one up.

The tooling declares none. Its colours are functions (`green("✅")`, `cyan(name)`), not a trait implemented once for `&str` so that they could be written as methods.

`dyn` appears only where the standard library's own signatures put it: a panic's payload (`&(dyn Any + Send)`) and `Error::source`. Nothing in the workspace chooses an implementation at run time; what varies is a closed set, and a closed set is an enum.

## Generics

A generic parameter is right where callers really pass different types (`Table<Key, Item>` holds nodes, edges or actors under ids of five kinds; `emphasis` reads the parser's `VecDeque` and a test's `Vec`; `first_free` opens a `TcpListener` or a test's stand-in) or where a closure is inlined (`Scan::take_while` takes `Test: FnMut(char) -> bool`). A reader that never looks at its items takes their type with no bound, as `Vec` does: `Cursor<'items, Item>` reads a slice of anything and sits in `scan`, beside `Scan`, below the parsers; only the block parser's lines use it, and made concrete it would pull `block::Line` down into the foundation. Parameters have names that say what they are (`Value`, `Places`, serde's `Format`, never `T`), and their bounds are written in one place, not split between the parameter list and the `where` clause (`multiple_bound_locations`), on the impl that needs them rather than on the struct that only holds the value (`cli::args::Parser<Rest>`). `impl Trait` in the parameters of a public function is refused (`impl_trait_in_params`), because a caller could not name the type; md2html has no public functions, and `impl Read` in `input::read_limited` takes a file, standard input or a test's bytes alike.
