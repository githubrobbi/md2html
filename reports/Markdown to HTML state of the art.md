# Close the link hole, then measure everything

md2html has one verified security bug that comes before everything else: **link URLs are not filtered by scheme**, so `[x](javascript:alert(1))` renders as `href="javascript:alert(1"` and `[b](data:text/html,hi)` renders as `href="data:text/html,hi"`. Every reference engine (cmark, comrak, markdown-rs) drops these URLs by default ([md2html ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md); [cmark](https://github.com/commonmark/cmark)). Quotes and raw HTML are already escaped, so the fix is a small URL allowlist, not a sanitizer. The rest of the picture holds up well. The 2025–2026 state of the art splits into two camps. Parsing engines (comrak, pulldown-cmark, markdown-rs) have all converged on CommonMark 0.31.2, with 652/652 spec examples, fuzzing and safe-by-default output. Page builders (pandoc `--embed-resources`, Quarto `embed-resources`) make one self-contained file, but only by inlining heavy libraries. md2html's *reader layer* (outline with scrollspy and breadcrumb, progress bar, ranked search, themes, text size, glossary, figure zoom, callouts) already matches or beats what those tools put in one offline file, and it does so with **zero runtime dependencies, a 468 KB binary and a ~36 KB page baseline**. Its real gaps are underneath: core Markdown that mis-renders silently (nested lists flatten, inline images break), no GFM footnotes, task lists or alerts, and **about 10 unit tests with no CI, spec harness or fuzzing**. To become world-class, md2html should keep its philosophy and adopt the leaders' engineering discipline: fix the link hole now, measure itself against the CommonMark suite, and then add the syntax AI agents actually write.

## A `javascript:` link passes through md2html untouched

Probe rendering against v0.3.3 confirmed the bug on two schemes. `[x](javascript:alert(1))` produced `href="javascript:alert(1"` (also showing a second bug: the `)` inside the URL ends it early and leaks into the text), and `[b](data:text/html,hi)` produced `href="data:text/html,hi"`. Escaping is otherwise sound. Quotes become `&quot;`, so no one can break out of the attribute, and raw HTML such as `<script>` is escaped, never passed through ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)). This is narrow but real. The attacker never needs to inject markup, only a link that runs when a reader clicks it. The exposure grows with md2html's main use case. AI coding agents write the Markdown, and they often paste in text from web pages, issues and email, so the source of a link is no longer the trusted author it used to be.

The industry answer is settled. cmark "scrubs raw HTML and `javascript:`, `vbscript:`, `data:`, `file:` links by default", with `--unsafe` as the opt-out ([cmark](https://github.com/commonmark/cmark)). comrak does the same and lets non-image `data:` through only in unsafe mode ([comrak RenderOptions](https://docs.rs/comrak/latest/comrak/struct.RenderOptions.html)). markdown-rs is "100% safe HTML by default" and requires `allow_dangerous_protocol` to change that ([markdown-rs](https://github.com/wooorm/markdown-rs)). OWASP's rule is to validate URLs against an allowlist of safe schemes before they reach `href` or `src` ([OWASP XSS Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)). For md2html this means normalizing first: strip ASCII whitespace and control characters, decode entities and percent-encoding in the scheme, and lowercase it. Then allow only `http`, `https`, `mailto`, `tel`, `#fragment` and relative URLs, and allow `data:image/(png|jpeg|gif|webp|avif)` only in `<img src>`. Every other URL becomes `#` or plain text. The same check applies to autolinks and reference definitions if those arrive. The fix belongs with a fix for balanced parentheses in link destinations, since both live in the same scanner.

A second layer is cheap and fits the "no network" promise. A `<meta http-equiv="Content-Security-Policy">` built from SHA-256 hashes of the exact inline `<script>` and `<style>` bytes, with `default-src 'none'`, `connect-src 'none'`, `object-src 'none'` and `base-uri 'none'`, turns "this page cannot phone home" from a claim into something the browser enforces ([MDN script-src hashes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src); [OWASP CSP](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html)). Three conditions come with it. Hashes cover inline blocks "but not event handlers", so the generated JS must use `addEventListener` and no `style="..."` attributes. The meta tag must come before the content it protects. And `frame-ancestors`, `sandbox` and `report-uri` do nothing in a meta CSP ([MDN frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)). One uncertainty needs testing before shipping: no current source says how `img-src 'self'` resolves for sibling images under `file://` in each browser. md2html links its images rather than embedding them, so this decides whether the CSP breaks local figures. A hostile-input test corpus should guard both layers. It should hold `javascript:`/`vbscript:`/`data:` in every spelling (entity-encoded, percent-encoded, with embedded tabs and newlines), plus `</script>` inside headings and code, to prove the embedded search index cannot be broken out of.

## Engines converged on 652 examples; page builders converged on inlining

The Rust engine field is mature. **comrak 0.59.0 (26 Oct 2026) passes 652/652 CommonMark 0.31.2 and 670/670 GFM examples** and has the broadest opt-in extension set: footnotes, alerts, math, front matter, description lists, wikilinks and more ([docs.rs comrak](https://docs.rs/crate/comrak/0.59.0)). **pulldown-cmark 0.13.x** is the pure-Rust, no-`unsafe` pull parser. Its 15 extension flags now include GitHub alerts, math, definition lists, heading attributes and wikilinks ([docs.rs Options](https://docs.rs/pulldown-cmark/latest/pulldown_cmark/struct.Options.html)). A rival project's benchmark puts it at about 275 MiB/s against comrak's 72 MiB/s ([ferromark README](https://docs.rs/crate/ferromark/0.1.4/source/README.md)). Another project's numbers reverse that order ([rushdown README](https://docs.rs/crate/rushdown/0.9.1/source/README.md)), so the speed rankings are self-reported and unsettled. **markdown-rs** claims 2,300+ tests, 100% coverage and two fuzzers, and still tells users to cap input size because crafted payloads can crash it ([markdown-rs](https://github.com/wooorm/markdown-rs)). In JavaScript, markdown-it leads downloads ([npm-compare](https://npm-compare.com/markdown-it,marked,micromark,remark,showdown)). TanStack recommends micromark or commonmark.js "when exact specification behavior is a requirement" ([TanStack comparison](https://tanstack.com/markdown/latest/docs/comparison)). None of these is std-only in md2html's sense. comrak in particular pulls in a long list of crates.

For a single self-contained page, the leaders are document systems, not parsers. **pandoc** (3.8 in Sep 2025, 3.9 in Feb 2026 with opt-in alerts) writes one file with `--embed-resources`, inlines assets as `data:` URIs, and now defaults to **MathML** math that "needs no JavaScript or fonts" ([pandoc manual](https://pandoc.org/MANUAL.html); [pandoc releases](https://github.com/jgm/pandoc/releases)). **Quarto** does the same with `embed-resources: true` and adds the richest reader layer of any single-document tool. Hover popups for footnotes, citations and cross-references are on by default, and it also offers margin notes, tabsets and `<details>` code folding ([Quarto HTML basics](https://quarto.org/docs/output-formats/html-basics.html); [Quarto article layout](https://quarto.org/docs/authoring/article-layout.html)). **Typst** made HTML export semantically complete but still experimental in 0.14 (Oct 2025), and 0.15 (Jun 2026) added MathML equations and bundle export ([Typst 0.14](https://typst.app/docs/changelog/0.14.0/); [Typst 0.15](https://typst.app/blog/2026/typst-0.15)). The docs-site generators (mdBook, MkDocs Material and its successor Zensical, VitePress, Starlight) build multi-page sites, but their navigation ideas carry over to one page ([MkDocs Material navigation](https://squidfunk.github.io/mkdocs-material/setup/setting-up-navigation/); [mdBook renderers](https://rust-lang.github.io/mdBook/format/configuration/renderers.html)). A newer category grew in 2025–2026: hosted "agent Markdown to shareable page" services. **md.page** publishes through an API or MCP, renders Mermaid, and anonymous pages expire after 24 hours ([md.page](https://md.page/)). RenderMark and mdview.io follow the same model ([RenderMark](https://rendermark.app/); [mdview.io](https://mdview.io/s/ai-markdown-viewer)).

## md2html's reader layer already rivals Quarto and Material

The verified feature list puts md2html near the top of single-file readers. It already ships the things researchers expected to list as gaps. Scrollspy highlights the current chapter, opens its sub-list, keeps the outline item in view and shows a "Chapter › Section" breadcrumb. A reading progress bar tracks scroll. Search opens in a `<dialog>` with Cmd/Ctrl-K or `/`, supports arrow keys and Enter, ranks title hits above body hits with a phrase bonus, and highlights matches with `<mark>` in its snippets ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)). That is roughly MkDocs Material's `toc.follow` plus `navigation.path` plus its `/` search key, inside one file ([MkDocs Material navigation](https://squidfunk.github.io/mkdocs-material/setup/setting-up-navigation/)). The cross-page glossary is rarer still. Material reaches something similar only by combining abbreviations with `pymdownx.snippets` auto-append across a site ([Material tooltips](https://squidfunk.github.io/mkdocs-material/reference/tooltips/)). md2html does it with nothing installed.

The size discipline is just as strong. A near-empty page is about 36 KB of CSS and JS, and the README renders to about 68 KB ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)). No published size budget exists for single-file documents. The standards research's rough target of 30 KB CSS plus 30 KB JS is an inference, not a standard, but md2html sits well inside it, while Quarto's `minimal: true` switch shows how much weight its full layer adds ([Quarto HTML basics](https://quarto.org/docs/output-formats/html-basics.html)). The binary is 468,336 bytes stripped, built from 1,755 lines of Rust in three files. Few tools in this space can state "runtime dependencies: 0" so plainly.

The reader gaps that remain are specific and verified. **Search does not highlight matches inside the page body** after the jump. Only a "landing glow" marks the target section, whereas Pagefind adds the query to the URL and highlights it on arrival ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md); [Pagefind highlighting](https://pagefind.app/docs/highlighting/)). **The print stylesheet is minimal.** It hides the bar, copy buttons and skip link and forces black on white. It does not hide the outline nav explicitly, print link URLs, avoid page breaks inside figures, tables and code, or print glossary definitions. mdBook builds a dedicated print page for the same need ([mdBook renderers](https://rust-lang.github.io/mdBook/format/configuration/renderers.html)). **Footnotes do not exist**, and that leaves an opening. md2html already has a hover-popover mechanism in its glossary, and Quarto treats hover footnotes as a default ([Quarto HTML basics](https://quarto.org/docs/output-formats/html-basics.html)). So GFM footnotes rendered as glossary-style popovers with back-links would turn a missing feature into a distinctive one.

Some accessibility details have not been verified either way, and they need an audit rather than an assumption. WCAG 2.2 AA is still the binding target. WCAG 3 remains a Working Draft that "will not supersede WCAG 2" ([W3C WCAG 3](https://www.w3.org/WAI/WCAG3)), and the EU Accessibility Act has applied since 28 June 2025 through EN 301 549 ([Siteimprove EAA FAQ](https://siteimprove.com/en/blog/the-european-accessibility-act-frequently-asked-questions/)). The custom widgets carry the most risk. Glossary hovers must be dismissible with Escape, hoverable and persistent under SC 1.4.13 ([Understanding 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)). The figure-zoom overlay is custom JS, and it should meet the modal dialog pattern of focus in, Tab trapped, Escape out and focus returned ([APG modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)). Search already uses `<dialog>`, so moving zoom onto the same element is the natural fix. Smaller verified items: `lang="en"` is hard-coded, the outline preference key `iv-toc` is shared by every md2html page on the same origin, the glossary chapter is still titled "The words in this book", and search reports "Nothing in the book matches that" on generic pages ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)).

## Silent mis-renders, not missing features, are the real gap

md2html's stated rule is that unknown syntax is shown verbatim rather than guessed. That is honest, and the readers of a handbook can see what was not understood. The verified bugs break that rule, because they change meaning without showing anything. **Nested lists flatten**: an indented `- nested` item becomes a sibling, which destroys the hierarchy of every outline-style plan an agent writes. **An inline image inside a paragraph renders as a literal `!` plus a link.** **`***bold italic***` mis-nests** into `<strong>*bi</strong>*`. **Parentheses inside a URL end it early** ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)). These are core CommonMark, not extensions. Djot, a redesign by CommonMark's own author, points to the same weak spots as Markdown's hardest areas: emphasis ("a daunting list of 17 rules"), nesting and links ([jgm/djot](https://github.com/jgm/djot)). The durable fix is to adopt CommonMark's two algorithms for these areas, a block container stack for list items and the delimiter stack for emphasis. Adding special cases on top of an ad-hoc scanner will not get there. Doing this does not require full compliance. md2html can stay a deliberate subset and still report an honest "N of 652" pass count.

The second layer is the syntax agents emit, which md2html currently shows verbatim: footnotes `[^1]`, task lists `- [ ]`, strikethrough `~~x~~`, math `$x^2$`, front matter, heading IDs `{#id}` and definition lists. The research found no measured distribution of the constructs LLMs produce, so the ordering here is a judgment. What is documented is that GFM tables, task lists, strikethrough, autolinks and footnotes form GitHub's baseline ([GitHub Docs](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)), and that **GitHub alerts** (`> [!NOTE]` with exactly five types) are now in pulldown-cmark, comrak and pandoc 3.9 ([docs.rs Options](https://docs.rs/pulldown-cmark/latest/pulldown_cmark/struct.Options.html); [comrak](https://docs.rs/crate/comrak/0.59.0); [pandoc releases](https://github.com/jgm/pandoc/releases)). Alerts are the cheapest win in the whole report. md2html already turns `> [!NOTE]` into a Note callout, but it prints the literal text "[!NOTE]" inside it. Recognizing the five types and keeping `> Note:` as an alias is close to a one-line change.

Behind all of this sits the largest structural gap: **testing**. md2html has about 10 unit tests, no conformance harness, no golden files, no fuzzing and no CI configuration ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)). The leaders all pair a spec harness with fuzzing. pulldown-cmark keeps one spec-format file per extension plus a running `regression.txt`, and it runs a separate DoS fuzzer for quadratic-time inputs ([pulldown-cmark specs](https://github.com/pulldown-cmark/pulldown-cmark/tree/master/pulldown-cmark/specs); [pulldown-cmark](https://github.com/pulldown-cmark/pulldown-cmark)). mdBook drives headless Chrome against built books in a separate CI job ([mdBook main.yml](https://docs.rs/crate/mdbook/0.5.3/source/.github/workflows/main.yml)). None of this breaks the std-only rule. The CommonMark suite ships as examples that `spec_tests.py --dump-tests` exports to JSON ([commonmark-spec](https://github.com/commonmark/commonmark-spec)), and a vendored file plus a small test helper can read them with std alone. Validators, axe-core and Playwright run in CI and never become runtime dependencies. Output is also not reproducible today, because the rendering date is stamped in the page header. Golden files and byte-identical rebuilds both need that stamp to become optional ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)).

## Agents now write the Markdown and read the HTML

The agent era settled on a few conventions md2html can meet offline. llms.txt v2 asks for a Markdown twin of each page (`page.html.md`), discoverable through `rel="alternate" type="text/markdown"` ([llmstxt.org](https://llmstxt.org/)). "Copy as Markdown" or "View as Markdown" buttons are now common on documentation sites, including Vercel, Mintlify, Fern, Cloudflare and Grafana ([Vercel](https://vercel.com/docs/agent-resources/markdown-access); [Mintlify](https://www.mintlify.com/docs/ai/markdown-export); [Grafana](https://grafana.com/whats-new/2026-05-15-grafana-documentation-now-ships-as-markdown/)). Hosted tools such as md.page reach agents through MCP ([md.page](https://md.page/)). md2html's single-file design gives it a built-in edge here. It can embed the original Markdown in a non-executing `<script type="text/markdown">` block and offer Copy and Download buttons. The page then round-trips, so any agent that receives the HTML can recover the exact source, with no server involved.

The CLI is the other half of agent fit. Today md2html takes one file per run, with no stdin/stdout, batch mode, watch or check mode ([ground truth](../research_notes/Markdown%20to%20HTML%20state%20of%20the%20art/md2html_ground_truth.md)). clig.dev's checklist covers what to add: `-` for stdin and stdout, primary output on stdout and messages on stderr, exit codes mapped to distinct failures, and atomic temp-file-then-rename writes ([clig.dev](https://clig.dev/)). The most valuable addition for agents is a `--check --json` mode. It would report the constructs md2html would show verbatim or render badly, such as unclosed fences, heading-level jumps, broken internal anchors, missing image files and rejected URL schemes, as `file:line:col` diagnostics. An agent could run it after writing a report and fix the problems before a human ever opens the page. That turns md2html's "show verbatim" philosophy from a quiet fallback into feedback the agent can act on. The positioning follows from this: md2html is md.page or RenderMark that runs locally, works offline, makes one file, has no dependencies, never expires and never uploads anything.

The philosophy also implies a list of things not to do. Do not inline the Mermaid, KaTeX or MathJax runtimes. They break the size and dependency promise, and pandoc's own manual warns that MathJax can lose its fonts under embedding ([pandoc manual](https://pandoc.org/MANUAL.html)). Leave ` ```mermaid ` fences as labelled code. Do not chase comrak's full extension list, since the leaders make every extension opt-in anyway ([comrak](https://docs.rs/crate/comrak/0.59.0)). Do not depend on platform features that work in only one engine, such as `interestfor` (Chromium only) or `text-wrap: pretty` (no Firefox), except as progressive enhancement ([web-features: interest invokers](https://web-platform-dx.github.io/web-features-explorer/features/interest-invokers/); [web-features: text-wrap-pretty](https://web-platform-dx.github.io/web-features-explorer/features/text-wrap-pretty/)).

## Conclusion

The research changes what "world-class" means for md2html. The tool does not need more reader features to compete. Its one-file reading experience is already near the top of the field, and it reaches that with no dependencies, which none of the fuller-featured tools can claim. What separates it from the leaders is that their quality can be checked: a spec count on the badge, a fuzzer in the repository, safe URLs by default. Those are all achievable with std alone, so the std-only rule is not a handicap. It becomes the headline once the claims behind it are measurable, along the lines of "zero runtime dependencies, N/652 CommonMark, a CSP-sealed page that cannot reach the network."

The agent era sharpens this. When the author is a coding agent pasting in text from the web, a renderer's safety and its `--check` diagnostics matter more than its theming. A tool that tells the agent "line 42 nests a list I will flatten" or "line 88 links to `javascript:`" gets the document fixed before a person reads it. md2html's verbatim-fallback philosophy already points that way. The roadmap above makes it explicit and enforced, starting with the link filter.
