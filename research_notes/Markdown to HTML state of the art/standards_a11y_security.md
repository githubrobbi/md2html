# Standards, accessibility, security and modern platform checklist for a self-contained generated HTML document page (late 2026)

Scope: what md2html's single-file output (inline CSS/JS, embedded search index, outline sidebar + hover drawer, light/dark/system themes, text size control, glossary hover tooltips, figure zoom overlay, callouts, code copy buttons, no network loads, opened from file:// or a server) should meet. Each item has a why and a how, ordered by impact within each section.

Method note: browser-support facts were checked this session (21 Nov 2026) against the web-features explorer (the data behind Baseline), web.dev monthly roundups, MDN, Chrome developer docs and Mozilla/Chromium intent threads. Stable WCAG 2.2 success-criterion facts and long-established MDN/OWASP references are cited to their canonical pages; those pages were not all re-fetched this session (see Gaps).

Impact legend used in the checklist items: **[P0]** = correctness/safety/legal, **[P1]** = strong user-facing quality, **[P2]** = polish / progressive enhancement.

## 1. Accessibility: WCAG 2.2 AA, WCAG 3/APCA, ARIA patterns, user preferences, EAA

### Takeaway
WCAG 2.2 AA remains the binding target (WCAG 3 is still a Working Draft that W3C says will not supersede WCAG 2, and APCA is not a conformance requirement anywhere). The highest-risk md2html features are the custom widgets: glossary tooltips (1.4.13, keyboard + touch), the figure zoom overlay (modal dialog pattern), the search box (combobox + status messages), and the sticky header/sidebar (2.4.11 focus not obscured). The EAA makes WCAG 2.1/2.2 AA via EN 301 549 a legal requirement for many EU e-books and services since 28 June 2025.

### Cited Findings

**Standards status**
- WCAG 3 is still a Working Draft; updated drafts were published in March and September 2026; W3C states WCAG 3 "will not supersede WCAG 2" and is not expected to be a completed standard "for a few more years"; the conformance model is still being refined — [W3C WCAG 3 Introduction](https://www.w3.org/WAI/WCAG3); [WCAG 3 WD March 2026](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/); [WCAG 3 explainer Sept 2026](https://www.w3.org/TR/2026/DNOTE-wcag-3.0-explainer-20260910/); [W3C news, March 2026 draft](https://www.w3.org/WAI/news/2026-03-03/wcag3)
- A secondary source says a WCAG 3 candidate recommendation is targeted for Q4 2027 (not confirmed by W3C) — [AbilityNet WCAG 3 overview 2026](https://abilitynet.org.uk/resources/digital-accessibility/what-expect-wcag-30-web-content-accessibility-guidelines)
- WCAG 2.2 (W3C Recommendation) is the current normative version; it added 2.4.11 Focus Not Obscured (Minimum, AA), 2.4.12 (AAA), 2.4.13 Focus Appearance (AAA), 2.5.7 Dragging Movements (AA), 2.5.8 Target Size (Minimum, AA, 24x24 CSS px or spacing exception), 3.2.6 Consistent Help (A), 3.3.7 Redundant Entry (A), 3.3.8/3.3.9 Accessible Authentication; 4.1.1 Parsing is obsolete/removed — [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- 1.4.13 Content on Hover or Focus (AA): additional content shown on hover/focus must be **dismissible** (without moving pointer/focus, typically Escape), **hoverable** (pointer can move onto it without it vanishing) and **persistent** (stays until hover/focus removed, dismissed, or no longer valid) — [Understanding 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)
- 2.4.11 Focus Not Obscured (Minimum): a focused component must not be entirely hidden by author-created content such as sticky headers/footers or non-modal overlays — [Understanding 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- 2.5.8 Target Size (Minimum): pointer targets at least 24x24 CSS px, with exceptions for spacing, inline targets in a sentence (so inline glossary terms and inline links are exempt), equivalents, UA-controlled and essential — [Understanding 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- Other AA criteria that directly govern document pages: 1.3.1 Info and Relationships (headings, lists, tables, figure captions as real markup), 1.4.3 Contrast (4.5:1 body text, 3:1 large text), 1.4.11 Non-text Contrast (3:1 for focus indicators, control borders, icons), 1.4.4 Resize Text (200%), 1.4.10 Reflow (no 2-D scrolling at 320 CSS px wide, except code blocks/tables which are exempt as content requiring 2-D layout), 1.4.12 Text Spacing (no loss of content when line-height 1.5, paragraph spacing 2x, letter 0.12em, word 0.16em), 2.1.1 Keyboard, 2.4.1 Bypass Blocks (skip link or landmarks), 2.4.2 Page Titled, 2.4.6 Headings and Labels, 2.4.7 Focus Visible, 3.1.1 Language of Page, 3.1.2 Language of Parts, 4.1.2 Name, Role, Value, 4.1.3 Status Messages (e.g. "12 results" in search announced without focus move) — [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

**ARIA patterns for md2html widgets**
- APG Tooltip pattern: container has `role="tooltip"`, trigger references it with `aria-describedby`; Escape dismisses; focus stays on the trigger; hover-triggered tooltip stays open while the pointer is over trigger or tooltip; "Tooltip widgets do not receive focus" — tooltips must not contain focusable elements; use a non-modal dialog if the popup needs interactive content. The pattern itself "does not yet have task force consensus" (work in progress) — [ARIA APG Tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)
- Chrome's interest-invoker tooltip guidance: interest triggers on hover or focus, toggletips also on long-press; pair `interestfor` with `popovertarget` so click/tap/Enter also open it; "Escape, light dismiss, and losing interest close it"; don't move focus into the tooltip; explicitly requires WCAG 1.4.13 (dismissible, hoverable, persistent); recommends still adding explicit ARIA because screen readers don't yet expose interest invokers consistently — [Chrome: Show a tooltip when hovering](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/interest-triggered-tooltips)
- APG Combobox pattern (for search-as-you-type): input `role="combobox"` with `aria-expanded`, `aria-controls` pointing to a `role="listbox"` popup, `aria-activedescendant` for the highlighted option, Down/Up arrows move through options, Enter accepts, Escape closes/clears — [ARIA APG Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
- APG Modal Dialog pattern (for figure zoom): focus moves into dialog on open, Tab is contained, Escape closes, focus returns to the invoking element, dialog has an accessible name (`aria-labelledby`/`aria-label`) — [ARIA APG Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- Native `<dialog>` opened with `showModal()` makes the rest of the page inert, provides Escape-to-close, the `::backdrop` pseudo-element and top-layer rendering — [MDN `<dialog>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog)
- `<dialog closedby="any">` (light-dismiss on backdrop click) is Limited availability: Chrome 134, Firefox 141, not Safari — [web-features: dialog-closedby](https://web-platform-dx.github.io/web-features-explorer/features/dialog-closedby/)
- Landmarks: one `<main>`, `<nav aria-label="...">` for the outline (labels distinguish multiple navs), `<header>`/`<footer>` at body level map to banner/contentinfo, `<search>` maps to the search landmark — [ARIA APG Landmark Regions](https://www.w3.org/WAI/ARIA/apg/practices/landmark-regions/); [MDN `<search>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/search)

**User-preference media features**
- `forced-colors: active` detects Windows High Contrast / forced colors; authors should use CSS system colors (`Canvas`, `CanvasText`, `LinkText`, `Highlight`, `ButtonText`, `GrayText`) and avoid relying on background-color/box-shadow alone for meaning; `forced-color-adjust: none` opts specific elements out (use sparingly, e.g. syntax swatches) — [MDN forced-colors](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/forced-colors)
- `prefers-reduced-motion` and `prefers-contrast` (`more`/`less`/`custom`) are long-standing media features — [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion); [MDN prefers-contrast](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-contrast)

**European Accessibility Act**
- EAA (Directive 2019/882) applies from 28 June 2025; e-books (as a service) and e-readers (as a product), e-commerce, banking and passenger transport are in scope; presumption of conformity is via harmonised standard EN 301 549, whose cited version v3.2.1 incorporates WCAG 2.1 AA; one source reports EN 301 549 v4.1.1 published Sept 2026 moving to WCAG 2.2 AA once cited in the Official Journal (not verified); microenterprise service providers (<10 staff, <=EUR 2M turnover) are exempt for services; "disproportionate burden" is the other carve-out — [Siteimprove EAA FAQ](https://siteimprove.com/en/blog/the-european-accessibility-act-frequently-asked-questions/); [Taylor Wessing on EAA exemptions](https://www.taylorwessing.com/en/interface/2025/accessibility/key-eu-accessibility-act-exemptions-and-the-challenges-they-pose); [Level Access](https://www.levelaccess.com/blog/eu-accessibility-requirements-and-eaa-compliance/); [DWT](https://www.dwt.com/insights/2025/07/european-accessibility-act-digital-products)

### Inferences (the accessibility checklist for md2html output)

1. **[P0] `<html lang="...">`** from front matter / CLI flag (default `en` only if truly unknown); emit `lang` on foreign-language spans when Markdown/attributes provide it (3.1.1, 3.1.2). Also `dir` (see section 5).
2. **[P0] Real semantic structure**: exactly one `<h1>` (the title), no skipped heading levels in generated chrome (never use headings for sidebar labels; lint the author's Markdown and warn on skips rather than rewriting); `<main>`, `<nav aria-label="Contents">` for the outline, `<search>` around the search box, `<header>`/`<footer>`; `<article>` around the document body is reasonable.
3. **[P0] Skip link** as the first focusable element (`<a class="skip" href="#main">Skip to content</a>`), visually hidden until focused; target `<main id="main" tabindex="-1">` so focus actually moves in all browsers (2.4.1).
4. **[P0] Glossary tooltips that meet 1.4.13 by keyboard and touch**: make each glossary term a focusable element (a `<button type="button">` styled inline, or an `<a href="#glossary-term">` linking to the definition so it degrades to a working link with JS off); open on hover AND focus; close on Escape without moving focus; keep open while the pointer is over the tooltip (no gap between trigger and tooltip, or a short hide delay); on touch, tap toggles (first tap shows, second tap or tap elsewhere closes, link activation on a separate affordance). Wire `aria-describedby` to a `role="tooltip"` element containing only plain text. If the tooltip contains links, it is no longer a tooltip; switch to a non-modal disclosure/popover (`aria-expanded` on the trigger) per APG.
5. **[P0] Figure zoom as a real modal dialog**: `<dialog aria-label="Figure 3: ...">` opened with `showModal()`, containing a visible Close `<button>` (first focusable), Escape closes (native), focus returns to the figure's trigger button, background is inert (native with showModal). Add a click-on-backdrop handler in JS because `closedby="any"` is not in Safari. The trigger must be a `<button>` (or the image wrapped in one) with an accessible name like "Enlarge figure 3", not a bare `<img onclick>`.
6. **[P0] Search as an APG combobox** (or a simpler pattern: input + live result list): `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-autocomplete="list"`; options `role="option"` with `aria-selected`; a polite live region (`role="status"`) that announces "N results" (4.1.3); visible `<label>` (or `aria-label`) on the input; `type="search"` and `enterkeyhint="search"`.
7. **[P0] Focus visible and not obscured**: a 2px+ `:focus-visible` outline with 3:1 contrast against adjacent colors in both themes (1.4.11, aiming at 2.4.13 AAA); `scroll-margin-top`/`scroll-padding-top` equal to the sticky header height so focused elements and heading anchors aren't hidden under it (2.4.11). The hover drawer must not cover the focused element in the reading column; if it overlays content, close it when focus leaves it.
8. **[P0] Contrast in all themes**: 4.5:1 body text, 3:1 for large text, UI borders, icons, focus rings — check every token pair (text/background, muted text, link, code token colors, callout borders/backgrounds) in light, dark, and at `prefers-contrast: more`. Syntax-highlighting palettes are the usual failure point (comments in low-contrast grey).
9. **[P1] Reflow/resize**: no horizontal page scroll at 320 CSS px and at 200%/400% zoom; code blocks and wide tables scroll inside their own container (`overflow-x: auto`) and that scroll container must be keyboard-reachable (`tabindex="0"` plus a label such as `role="region" aria-label="Code: rust"`), since otherwise keyboard users cannot scroll it. The text-size control should scale `rem` (root font-size), not use `zoom` or `transform`.
10. **[P1] Text spacing (1.4.12)**: no fixed heights on text containers (callouts, tooltips, sidebar items), so user stylesheets that raise line-height/letter-spacing don't clip.
11. **[P1] Tables**: `<th scope="col">` for header rows (GFM tables have one header row, so `scope="col"` is always correct), `<caption>` when the author provides one (e.g. a preceding "Table: ..." line convention), wrap in a scrollable focusable region.
12. **[P1] Figures**: `<figure>` + `<figcaption>` when an image has a title/caption; `alt` passed through verbatim; empty `alt=""` for decorative images; warn at build time on missing alt (don't invent alt text). Do not duplicate the caption into `alt`.
13. **[P1] Copy buttons**: real `<button type="button" aria-label="Copy code">`, minimum 24x24 px target (2.5.8), confirmation announced via a live region ("Copied") rather than only an icon change; visible on focus, not only on hover.
14. **[P1] Theme and text-size controls**: radio group or buttons with `aria-pressed`, labels in text (not icon-only without name); state persisted best-effort (see section 3 on file:// storage).
15. **[P1] User preferences**: wrap every transition/animation (drawer slide, tooltip fade, zoom, view transitions, scroll progress) in `@media (prefers-reduced-motion: no-preference)`; under `prefers-contrast: more` strengthen borders and remove translucent backgrounds; under `forced-colors: active` use system colors for focus rings, callout borders, active outline item (backgrounds are flattened, so meaning carried by background color alone disappears; add borders or icons).
16. **[P1] Callouts**: carry the type in text (visually present or visually-hidden "Warning:" prefix), not only via color/icon; consider `role="note"` (or `aside` only if truly tangential). Icons `aria-hidden="true"`.
17. **[P1] Heading anchors**: self-links next to headings need an accessible name ("Link to section: Installation") or should be the heading text itself; avoid announcing "#" to screen readers.
18. **[P2] Current outline item**: mark with `aria-current="true"` (or `"location"`) as the reader scrolls, not just a class.
19. **[P2] Screen reader testing matrix** (manual, per release): NVDA + Firefox/Chrome, JAWS + Chrome, VoiceOver + Safari (macOS and iOS), TalkBack + Chrome; plus Windows forced-colors mode and 400% zoom. Automated tools catch only a subset of WCAG issues, so the custom widgets need scripted keyboard tests (section 7).
20. **[P2] Contrast method**: compute WCAG 2 contrast ratios for conformance; APCA may be used as an additional design check for dark mode readability, but not as the pass/fail criterion while WCAG 3 is a draft.
21. **EAA relevance**: md2html is a tool, not a covered service, but its users (publishers of e-books, documentation on e-commerce/banking sites in the EU) inherit obligations; shipping WCAG 2.2 AA-capable output by default is a selling point and cheap insurance.

### Gaps
- The current APCA position inside the September 2026 WCAG 3 draft was not retrieved (search returned nothing specific); treat "APCA is not normative anywhere" as true for WCAG 2.x and unknown-in-detail for the WCAG 3 draft.
- Whether EN 301 549 v4.1.1 (WCAG 2.2 AA) has been cited in the EU Official Journal could not be confirmed; only a secondary source mentions its publication.
- WCAG 2.2 SC details above are from the canonical W3C pages but those pages were not re-fetched in this session.
- No authoritative cross-browser data was found on whether browser find-in-page auto-opens closed `<details>` in Safari (Chrome and Firefox are known to; verify).

## 2. Modern platform features that can replace custom JS (support as of Nov 2026)

### Takeaway
Use natively and Baseline-safe now: `<dialog>`, Popover API (`auto`/`manual`), invoker commands (Baseline Dec 2025), CSS anchor positioning (Baseline Newly available Jan 2026), `light-dark()` + `color-scheme`, `:has()`, container queries, `<search>`, `<details name>`, `text-wrap: balance`, `content-visibility`, `scroll-margin-top`, scroll-driven animations (Baseline Newly available Oct 2026). Treat as progressive enhancement only (not in Safari or Firefox): `popover="hint"`, interest invokers (`interestfor`), `hidden="until-found"`, `interpolate-size`, `text-wrap: pretty` (no Firefox), `dialog closedby`. Because the page must work offline in all browsers, every Limited feature needs a JS or CSS fallback, and because "Newly available" Baseline features are only ~months old, keep `@supports` fallbacks for anchor positioning and scroll-driven animations for users on older browsers.

### Cited Findings
- **CSS anchor positioning**: Firefox 147 (13 Jan 2026) made it Baseline Newly available; it is in Interop 2026 as a carryover; anchor-positioning transforms sub-feature still unsupported in Firefox — [web.dev: New to the web platform in January 2026](https://web.dev/blog/web-platform-01-2026); [CodePen blog](https://blog.codepen.io/?p=20947); [caniuse: anchor positioning transforms](https://caniuse.com/wf-anchor-positioning-transforms)
- With interest invokers the trigger is an implicit anchor (no `anchor-name` needed); Chrome's recipe uses `position-area: block-start` with `position-try-fallbacks: flip-block`, plus `inset: auto; margin: 0` to override popover UA centering; without anchor support popovers center in the viewport, so wrap positioning in `@supports` or polyfill with `@oddbird/css-anchor-positioning` — [Chrome interest-triggered tooltips](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/interest-triggered-tooltips)
- **Invoker commands** (`command`/`commandfor`): Chrome 135, Firefox 144, Safari 26.2; MDN lists Baseline Newly available since December 2025; built-in commands include `show-modal`, `close`, `request-close`, `toggle-popover`/`show-popover`/`hide-popover`; custom commands use a `--` prefix and fire a `command` event — [InfoQ, Jan 2026](https://www.infoq.com/news/2026/01/html-invoker-commands); [MDN Invoker Commands API](https://developer.mozilla.org/docs/Web/API/Invoker_Commands_API); [caniuse](https://caniuse.com/wf-invoker-commands). Note: the web-features explorer page still showed "blocked by Safari" when searched, which conflicts with MDN/caniuse and looks stale — [web-features: invoker-commands](https://web-platform-dx.github.io/web-features-explorer/features/invoker-commands/)
- **`popover="hint"`**: Limited availability — Chrome 151 (full), Firefox 153, Safari not supported; "blocked since July 2026 by Safari" — [web-features: popover-hint](https://web-platform-dx.github.io/web-features-explorer/features/popover-hint/). (Conflict: Mozilla's intent-to-ship targeted Firefox 149 and caniuse shows partial support in Chrome from 133 — [Mozilla intent](https://groups.google.com/a/mozilla.org/g/dev-platform/c/OGdRzK18_Zo); [caniuse popover hint](https://caniuse.com/wf-popover-hint); the explorer's versions likely reflect when the full feature landed.) Where `hint` is unsupported it falls back to `manual`; the popover polyfill does not cover `hint` — [Chrome guide](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/interest-triggered-tooltips)
- **Interest invokers (`interestfor`)**: Limited availability — Chrome/Edge 149 (June 2026) only; Firefox and Safari not supported — [web-features: interest-invokers](https://web-platform-dx.github.io/web-features-explorer/features/interest-invokers/); [MDN Using interest invokers](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using_interest_invokers); polyfill detection: load only when `interestForElement` is missing from `HTMLButtonElement.prototype` — [Chrome guide](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/interest-triggered-tooltips)
- **`hidden="until-found"`**: Limited — Chrome 102, Firefox 148 (Feb 2026), Safari not supported (caniuse snapshots conflict, one showing partial support in Safari 26.2+) — [web-features: hidden-until-found](https://web-platform-dx.github.io/web-features-explorer/features/hidden-until-found/); [caniuse](https://caniuse.com/wf-hidden-until-found). Chrome advises using it anyway with a JS fallback for its accessibility benefit — [Chrome: search hidden content](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/search-hidden-content.md.txt)
- **`<details name>` exclusive accordions**: Chrome/Edge 120, Firefox 130, Safari 17.2 — [MDN blog: exclusive accordions](https://developer.mozilla.org/en-US/blog/html-details-exclusive-accordions); [Chrome: Exclusive accordion](https://developer.chrome.com/docs/css-ui/exclusive-accordion)
- **`interpolate-size`** (animate to `height: auto`): Limited — Chrome 129 only; Firefox and Safari have positive positions but no support — [web-features: interpolate-size](https://web-platform-dx.github.io/web-features-explorer/features/interpolate-size/); [Builder.io animated accordions](https://builder.io/blog/animated-css-accordions)
- **`text-wrap: pretty`**: Limited — Chrome 117, Safari 26 (Sept 2025), not Firefox ("blocked since September 2025 by Firefox") — [web-features: text-wrap-pretty](https://web-platform-dx.github.io/web-features-explorer/features/text-wrap-pretty/)
- **Scroll-driven animations**: Firefox 159 enabled them by default in October 2026, making them Baseline Newly available with Chrome and Safari — [web.dev: New to the web platform in October 2026](https://web.dev/blog/web-platform-10-2026)
- **`light-dark()` with `<image>` values** became Baseline Newly available with Safari 27 (Sept 2026); the colour form of `light-dark()` has been Baseline since 2024 — [web.dev: September 2026](https://web.dev/blog/web-platform-09-2026); [MDN light-dark()](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark). `light-dark()` resolves according to the element's used `color-scheme`, so setting `color-scheme: light` or `dark` on `:root` forces a theme — [MDN light-dark()](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark)
- Other relevant Baseline items from Sept/Oct 2026 roundups: `alpha()` relative colour function, `progress()` CSS function, `revert-rule`, `overflow-anchor` (scroll anchoring, Safari 27), `sizes="auto"` for lazy images (Safari 27), typed arithmetic in `calc()` — [web.dev Sept 2026](https://web.dev/blog/web-platform-09-2026); [web.dev Oct 2026](https://web.dev/blog/web-platform-10-2026)
- `content-visibility: auto` skips rendering off-screen content while keeping it in the accessibility tree and find-in-page; pair with `contain-intrinsic-size` to avoid scrollbar jumps — [MDN content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/content-visibility)
- Text Fragments (`#:~:text=`) let readers deep-link to arbitrary text; supported in Chromium, Safari and Firefox (Firefox since 131); `::target-text` styles the highlight — [MDN Text fragments](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment/Text_fragments)

### Inferences (platform-feature checklist)

1. **[P1] Themes with `color-scheme` + `light-dark()`**: define tokens once, e.g. `--bg: light-dark(#fff, #111)`; `:root { color-scheme: light dark }` for "system", and the theme toggle just sets `:root[data-theme=light] { color-scheme: light }` / `[data-theme=dark] { color-scheme: dark }`. This also themes native scrollbars, form controls and the `<dialog>` backdrop. Apply the saved theme in a tiny blocking inline script in `<head>` before first paint to avoid a flash. Keep `<meta name="color-scheme" content="light dark">`.
2. **[P1] Figure zoom with `<dialog>` + invoker commands**: `<button commandfor="zoom" command="show-modal">` works without JS for open/close (Baseline Dec 2025); JS still needed to inject the clicked image, so listen to the dialog's `command` event or keep a single delegated click handler. Fallback: feature-detect `'commandForElement' in HTMLButtonElement.prototype` and call `showModal()` manually for older Safari/Firefox.
3. **[P1] Glossary tooltips**: build on JS with `popover="manual"` (Baseline) or a plain absolutely positioned element; position with CSS anchor positioning inside `@supports (anchor-name: --a)` and a small JS fallback for browsers older than the Jan 2026 Baseline. Optionally enhance with `interestfor` + `popover="hint"` where supported (Chromium only), but don't depend on it; Safari lacks both. Add explicit ARIA regardless.
4. **[P1] Outline drawer**: `popover="auto"` gives light-dismiss and Escape for free when it is opened as an overlay (narrow screens); invoker `command="toggle-popover"` opens it without JS. A persistent wide-screen sidebar should be a normal `<nav>`, not a popover.
5. **[P1] `scroll-margin-top` on `:target`/headings** (and `scroll-padding-top` on `html`) sized to the sticky header, so anchor jumps, Text Fragment jumps and focus don't land under chrome.
6. **[P1] Collapsible sections**: use `<details>`/`<summary>` (native, keyboard accessible); `name` for exclusive groups if a feature needs them; for content that must be collapsed yet findable, use `hidden="until-found"` with a `beforematch` handler plus a JS fallback (Safari). Before printing, open all `<details>` via `beforeprint`.
7. **[P2] Reading progress bar with scroll-driven animation**: `animation-timeline: scroll(root)` under `@supports (animation-timeline: scroll())` and `prefers-reduced-motion: no-preference`; zero JS. Mark `aria-hidden="true"` (decorative).
8. **[P2] `text-wrap: balance` on headings/captions (Baseline), `text-wrap: pretty` on paragraphs** (harmless where unsupported).
9. **[P2] `:has()`** for state styling without JS, e.g. `figure:has(img[alt=""])`, `body:has(dialog[open]) { overflow: hidden }`, `pre:has(> code.language-diff)`.
10. **[P2] Container queries** for callouts/figures/tables that adapt to the reading-column width rather than the viewport (the column width changes when the sidebar opens).
11. **[P2] View Transitions** (same-document) for theme switch cross-fade or zoom-in animation; strictly optional, gated on `document.startViewTransition` existence and reduced-motion. (Support as of late 2026 was not re-verified this session; see Gaps.)
12. **[P2] `interpolate-size: allow-keywords`** on `:root` to animate `<details>` open/close in Chromium; no effect elsewhere.
13. **[P2] `::target-text`** styled in both themes so Text Fragment highlights are visible; heading permalinks make a document citeable, Text Fragments make any sentence citeable for free.
14. **[P2] `<search>` element** as the wrapper for the search box (landmark without ARIA).

### Gaps
- View Transitions (same-document) Baseline date and `@page` margin boxes support in Firefox/Safari were not re-verified this session (the web-features page for page margin boxes returned 404).
- `hidden="until-found"` Safari status is contested between caniuse snapshots (unsupported vs partial in 26.2+); the web-features explorer says unsupported.
- `popover="hint"` Firefox version conflicts (149 per intent, 153 per web-features).
- Customizable `<select>` (`appearance: base-select`) status not researched (not needed for md2html).

## 3. Security for HTML generated from untrusted Markdown

### Takeaway
The generator is the security boundary: escape all text and attribute output, allowlist URL schemes after normalization, sanitize or escape raw HTML by default, and safely embed the JSON search index. Then lock the file down with a `<meta http-equiv="Content-Security-Policy">` built from SHA-256 hashes of the exact inline `<script>` and `<style>` contents with `default-src 'none'`, which also mechanically enforces the "no network loads" promise. `frame-ancestors`, `report-uri`/`report-to` and `sandbox` are ignored in a meta CSP.

### Cited Findings
- CSP hash sources: the hash covers the content between the tags (not the tags), "capitalization and whitespace matter, including leading or trailing whitespace"; supported algorithms sha256, sha384, sha512; hashes allow inline scripts and styles "but not event handlers"; inline handlers need `'unsafe-hashes'` plus the handler's hash, and the preferred fix is `addEventListener` — [MDN CSP script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src)
- `frame-ancestors` "is not supported in the `<meta>` element"; `sandbox` and `report-uri` are likewise header-only — [MDN frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors); [content-security-policy.com meta examples](https://content-security-policy.com/examples/meta); [Invicti](https://invicti.com/web-vulnerability-scanner/vulnerabilities/invalid-content-security-policy-csp-directive-identified-in-meta-elements)
- OWASP CSP guidance: prefer `default-src 'none'`/`'self'`, `object-src 'none'`, `base-uri 'none'`, nonces or hashes over `'unsafe-inline'`; meta-delivered CSP must appear before the content it protects — [OWASP CSP Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html)
- OWASP XSS prevention: context-specific output encoding (HTML body, attribute, URL, JS, CSS contexts differ); validate URLs to allow only safe schemes (http/https) before placing user data in `href`/`src`; when allowing user HTML, use a well-tested allowlist sanitizer — [OWASP XSS Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)
- Rust ecosystem: `ammonia` is an allowlist HTML sanitizer built on html5ever (used to clean rendered Markdown) — [ammonia](https://github.com/rust-ammonia/ammonia); comrak escapes raw HTML and "dangerous" URLs (javascript:, vbscript:, file:, non-image data:) unless the `unsafe_` render option is enabled — [comrak docs](https://docs.rs/comrak/latest/comrak/struct.RenderOptions.html)
- **Trusted Types**: Baseline Newly available since February 2026 (Chrome 83+, Safari 26, Firefox 148, with some caniuse disagreement on Firefox 148's default) — [MDN Trusted Types API](https://developer.mozilla.org/en-US/docs/Web/API/Trusted_Types_API); [Mozilla intent to ship](https://groups.google.com/a/mozilla.org/g/dev-platform/c/WA8vLAbvzB0); [caniuse trusted-types](https://caniuse.com/trusted-types); [web.dev Trusted Types](https://web.dev/articles/trusted-types). Enforced via CSP `require-trusted-types-for 'script'` — [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Trusted_Types_API)
- **file:// origins**: the spec leaves the origin of file URLs to the browser; Safari has treated each file URL as a unique origin since 11.1; Firefox moved to per-file unique origins (pref `privacy.file_unique_origin`), while Chromium has historically treated file pages as sharing an origin for storage; older reports show localStorage on file:// failing to persist in Firefox — [Chromium "file:// unique origin" intent](https://groups.google.com/a/chromium.org/g/blink-dev/c/--KjSROtcMQ); [Mozilla bug 1730419](https://bugzilla.mozilla.org/show_bug.cgi?id=1730419); [Mozilla bug 507361](https://bugzilla.mozilla.org/show_bug.cgi?id=507361); [W3C bug 11419](https://www.w3.org/Bugs/Public/show_bug.cgi?id=11419). These sources date from 2009-2021; current behaviour was not re-verified.
- `target="_blank"` now implies `rel="noopener"` in current browsers; `noopener` prevents the opened page from accessing `window.opener` — [MDN rel=noopener](https://developer.mozilla.org/en-US/docs/Web/HTML/Attributes/rel/noopener)
- Subresource Integrity applies to external resources via the `integrity` attribute; for CSP, an external script loads only if its `integrity` hashes match allowed CSP hashes — [MDN CSP script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src)

### Inferences (security checklist)

1. **[P0] Escape everything by default**: text nodes escape `& < >`; attribute values always quoted and escape `& < > " '`; heading IDs/slugs, glossary keys, figure captions, front-matter title/description all go through the same escaper (front matter is the commonly forgotten path, especially into `<title>`, `<meta content>` and JSON-LD).
2. **[P0] URL allowlist after normalization**: strip ASCII whitespace/control chars, percent-decode the scheme, lowercase, then allow only `http`, `https`, `mailto`, `tel`, fragment `#...` and relative URLs; allow `data:image/(png|jpeg|gif|webp|avif)` only in `<img src>` (never `data:text/html` or `image/svg+xml` in `href`). Drop or neutralize `javascript:`, `vbscript:`, `data:` in links, `file:` unless explicitly opted in. Apply to links, images, autolinks, reference definitions, and HTML attributes that survive sanitization (`href`, `src`, `srcset`, `poster`, `xlink:href`, `formaction`).
3. **[P0] Raw HTML policy**: default "safe" mode escapes or sanitizes raw HTML with an allowlist (ammonia): drop `<script>`, `<style>` (or sanitize), `<iframe>`, `<object>`, `<embed>`, `<form>`, `<base>`, `<meta>`, `<link>`, all `on*` attributes, `style` attributes (or strictly filter), `srcdoc`, `formaction`. Offer an explicit `--unsafe-html` flag for trusted input only, and with it relax CSP accordingly. Note: inline SVG from Markdown is an XSS vector (scripts, `on*`, `<foreignObject>`); sanitize it as HTML.
4. **[P0] Embedded JSON (search index, glossary)**: put it in `<script type="application/json" id="search-index">` and escape `<` as `<` (covers `</script>` and `<!--`), plus ` `/` `; parse with `JSON.parse(el.textContent)`. Never build it into a JS string literal or use `innerHTML` with index content; render results with `textContent`/DOM creation and highlight matches by splitting text, not by HTML injection. Data blocks (non-JS `type`) are not executed and don't need a CSP hash.
5. **[P0] CSP meta tag with hashes** as the first element after `<meta charset>` in `<head>` (it only applies to content after it). Suggested policy for a pure self-contained page:
   `default-src 'none'; script-src 'sha256-<inline-js>' ; style-src 'sha256-<inline-css>'; img-src 'self' data: blob:; font-src data:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'; media-src 'self' data:; require-trusted-types-for 'script'; trusted-types md2html`
   Compute hashes in Rust over the exact bytes emitted (after minification); whitespace changes break them, so generate the CSP last. Consequences: no inline `on*` handlers, no `style="..."` attributes from the generator (use classes or CSS custom properties set via CSSOM, which CSP does not block), no `eval`/`new Function`, no `innerHTML` with strings once Trusted Types is required (create a single named policy or avoid HTML sinks entirely). `img-src 'self'` lets local relative images load; whether `'self'` matches sibling files under file:// varies by browser (test; may need `file:` in a local-only mode). `connect-src 'none'` is a verifiable guarantee that the page cannot phone home.
6. **[P0] Links**: external links without `target` are the safest default; if `target="_blank"` is offered, emit `rel="noopener noreferrer"` explicitly (older engines) and announce "opens in new tab" (visually hidden text or icon with label). Consider `referrerpolicy="no-referrer"` globally via `<meta name="referrer" content="no-referrer">` for privacy of local paths.
7. **[P1] Storage on file:// is best-effort**: wrap every `localStorage` access in try/catch (Safari/Firefox privacy modes and file:// can throw or be ephemeral); namespace keys (e.g. `md2html:v1:theme`) because in Chromium all file:// documents may share one storage area, so one document's preference becomes every document's preference (acceptable for theme/text-size, wrong for per-document state like scroll position, which should key by document identity, e.g. a content hash). Fall back to `prefers-color-scheme` with no stored value.
8. **[P1] Clipboard**: `navigator.clipboard.writeText` requires a secure context; `file://` is treated as potentially trustworthy in Chromium and Firefox, but have a fallback (select text + `document.execCommand('copy')`, or select-and-instruct) and handle rejection gracefully. (Secure-context status of file:// in Safari not verified — see Gaps.)
9. **[P2] SRI is not applicable** (no external resources); if a CDN/math/diagram mode is ever added, require `integrity` + `crossorigin`, and note that CSP hashes can then pin them too.
10. **[P2] Don't leak local paths**: avoid emitting absolute source paths (`/Users/name/...`) into the HTML (generator meta, source maps, error messages, image `src`), since generated documents get shared.

### Gaps
- Current (2026) per-browser localStorage behaviour on file:// was not found in a primary, current source; the cited reports are 2009-2021. Recommend a manual test matrix.
- Whether Safari treats file:// as a secure context for `navigator.clipboard` was not verified.
- How CSP `'self'` resolves for file:// documents per browser was not verified.
- comrak's precise list of "dangerous" URL schemes is from its docs (not re-fetched); md2html's own Markdown library choice was not checked.

## 4. Print and PDF

### Takeaway
Ship a dedicated `@media print` stylesheet: force the light palette, hide chrome (sidebar, search, buttons, overlays), expand collapsed content, avoid breaks inside code/figures/tables and after headings, print external link URLs, and use `@page` size/margins. Chrome 131+ supports `@page` margin boxes for author-defined running headers/footers and page numbers; treat them as an enhancement.

### Cited Findings
- Chrome 131 added `@page` margin boxes (16 at-rules such as `@top-center`, `@bottom-right`, each nested in `@page`, filled with generated content like `::before`/`::after`), so printed pages and PDF exports can carry author headers/footers in place of the browser's; they don't show if page margins are zero or too small; browser headers/footers can be turned off in the print dialog; follows CSS Paged Media Level 3 — [Chrome: Add content to the margins of web pages when printed](https://developer.chrome.com/blog/print-margins); [New in Chrome 131](https://developer.chrome.com/blog/new-in-chrome-131); [Intent to Ship: @page margin boxes](https://groups.google.com/a/chromium.org/g/blink-dev/c/XKb6IQZXNks)
- Fragmentation properties `break-before`, `break-after`, `break-inside` (`avoid`, `avoid-page`) control page breaks; `orphans`/`widows` are honoured in Chromium — [MDN break-inside](https://developer.mozilla.org/en-US/docs/Web/CSS/break-inside)
- `print-color-adjust: exact` asks the browser to print backgrounds/colors as authored — [MDN print-color-adjust](https://developer.mozilla.org/en-US/docs/Web/CSS/print-color-adjust)
- `beforeprint`/`afterprint` events let scripts adjust the document before printing — [MDN beforeprint](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeprint_event)

### Inferences (print checklist)
1. **[P1] Light palette in print**: `@media print { :root { color-scheme: light } }` (with `light-dark()` tokens this flips everything); code highlighting in a print-safe palette; avoid printing large dark backgrounds.
2. **[P1] Hide chrome**: sidebar, drawer, search, theme/text-size controls, copy buttons, zoom dialog, skip link, progress bar: `display: none`.
3. **[P1] Expand content**: on `beforeprint`, open all `<details>` and reveal `hidden="until-found"` content; restore on `afterprint`. Tooltip glossary definitions: either append a printed glossary section or render definitions as footnotes.
4. **[P1] Breaks**: `h1..h6 { break-after: avoid }`, `pre, figure, table, blockquote, .callout { break-inside: avoid }` (allow long `pre` to break: use `avoid` only below a size threshold or accept breaking), `img { max-width: 100% }`, wrap long code lines in print (`white-space: pre-wrap`) since horizontal scroll doesn't exist on paper.
5. **[P1] Link URLs**: `a[href^="http"]::after { content: " (" attr(href) ")"; }` for external links only (skip internal `#` links and links whose text already equals the URL); `overflow-wrap: anywhere` for long URLs.
6. **[P2] `@page`**: `@page { size: auto; margin: 18mm 16mm }`; margin boxes for running title and `counter(page) " / " counter(pages)` in Chrome 131+; other engines simply fall back to browser headers. Avoid `size` that forces a paper format.
7. **[P2] Print-only metadata**: optionally show source/date/URL block at the top only in print.

### Gaps
- Firefox and Safari support for `@page` margin boxes was not verified this session (web-features page 404). Firefox has historically not supported margin boxes; confirm before documenting.

## 5. Metadata, i18n and RTL

### Takeaway
A world-class standalone page has a correct `<head>` order (charset, viewport, CSP, title, description, color-scheme, theme-color, inline SVG favicon, generator), `lang`/`dir` driven by the document, logical CSS properties so RTL works, and localized UI strings. Open Graph, canonical and JSON-LD only matter when the file is served on the web, so emit them when the user supplies a canonical URL.

### Cited Findings
- `<meta charset="utf-8">` must be within the first 1024 bytes; `<meta name="viewport" content="width=device-width, initial-scale=1">` for mobile layout — [MDN `<meta>` charset](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/meta#charset); [MDN viewport meta](https://developer.mozilla.org/en-US/docs/Web/HTML/Viewport_meta_tag)
- `<meta name="color-scheme" content="light dark">` lets the browser render the initial canvas and controls in the right scheme before CSS loads, avoiding a white flash — [MDN meta name=color-scheme](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/meta/name/color-scheme)
- `<meta name="theme-color">` accepts a `media` attribute so light and dark values can differ — [MDN theme-color](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/meta/name/theme-color)
- Open Graph minimum properties: `og:title`, `og:type`, `og:image`, `og:url` — [ogp.me](https://ogp.me/)
- schema.org `Article`/`TechArticle` with `headline`, `datePublished`, `dateModified`, `author`, `inLanguage` — [schema.org Article](https://schema.org/Article); [schema.org TechArticle](https://schema.org/TechArticle)
- `dir="auto"` lets the browser pick direction from content; `<bdi>` isolates bidirectional runs; CSS logical properties (`margin-inline-start`, `inset-inline-end`, `padding-block`) flip automatically for RTL — [MDN dir](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/dir); [MDN CSS logical properties](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_logical_properties_and_values)
- `translate="no"` tells translation tools not to translate content (useful on code) — [MDN translate](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/translate)

### Inferences (metadata checklist)
1. **[P0] Head order**: `<meta charset="utf-8">` -> viewport -> CSP meta -> `<title>` (document title, optionally "Title - Site") -> description -> `color-scheme` -> `theme-color` (two, with `media="(prefers-color-scheme: ...)"`) -> favicon -> generator -> theme-boot inline script -> style.
2. **[P1] `<meta name="description">`** from front matter or the first paragraph (plain text, escaped, ~155 chars).
3. **[P1] Favicon as inline SVG data URI**: `<link rel="icon" href="data:image/svg+xml,...">` (URL-encode `#`, `<`, `>`); allowed by `img-src data:` in the CSP. Can embed a `prefers-color-scheme` media query inside the SVG.
4. **[P1] `lang` and `dir`**: from front matter/CLI; set `dir="rtl"` for Arabic/Hebrew/Persian/Urdu documents; author all chrome CSS with logical properties (sidebar on `inline-start`, drawer slides from `inline-start`, callout border on `border-inline-start`); code blocks keep `dir="ltr"`; search results and outline entries use `dir="auto"` or `<bdi>` for mixed-direction headings.
5. **[P1] Localized UI strings**: all generated strings ("Contents", "Search", "Copy", "Copied", "Close", "Enlarge figure", "N results", "Skip to content", "Theme", ARIA labels) in a locale table selected by `lang`, with plural handling for counts (`Intl.PluralRules`); numbers via `Intl.NumberFormat`.
6. **[P2] `<meta name="generator" content="md2html 0.3.x">`**: useful for support and bug reports; no absolute paths.
7. **[P2] When a canonical URL is provided**: `<link rel="canonical">`, Open Graph (`og:title`, `og:description`, `og:type=article`, `og:url`, `og:image` only if absolute), and JSON-LD `TechArticle` in `<script type="application/ld+json">` (data block, no CSP hash needed; escape `<` as in section 3). Omit them otherwise; relative OG URLs are useless.
8. **[P2] `translate="no"` on `<pre>`/`<code>`** so page translators don't mangle code.

### Gaps
- No source consulted on whether search engines/link unfurlers read OG from file:// (they don't fetch local files, so the point is moot unless served).

## 6. Performance

### Takeaway
For a self-contained document the budget is about the inline payload and main-thread work on huge documents: keep chrome CSS+JS small (tens of KB, not hundreds), use system font stacks, reserve image space to avoid layout shift, and scale to thousands of headings with `content-visibility`, event delegation, a single IntersectionObserver, and a compact, lazily parsed search index.

### Cited Findings
- `content-visibility: auto` + `contain-intrinsic-size: auto <length>` skips layout/paint of off-screen sections while keeping them searchable and accessible; `auto` in `contain-intrinsic-size` remembers last rendered size — [MDN content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/content-visibility); [MDN contain-intrinsic-size](https://developer.mozilla.org/en-US/docs/Web/CSS/contain-intrinsic-size)
- Width/height attributes on `<img>` let the browser compute aspect ratio before load, preventing layout shift (CLS) — [web.dev Optimize CLS](https://web.dev/articles/optimize-cls)
- `system-ui` and `ui-monospace` generic families map to the platform UI fonts — [MDN font-family](https://developer.mozilla.org/en-US/docs/Web/CSS/font-family)
- `sizes="auto"` for lazy-loaded images became Baseline with Safari 27 (Sept 2026) — [web.dev Sept 2026](https://web.dev/blog/web-platform-09-2026)
- `overflow-anchor` scroll anchoring became Baseline with Safari 27 — keeps reading position stable when content above changes (e.g. images decoding, details opening) — [web.dev Sept 2026](https://web.dev/blog/web-platform-09-2026)

### Inferences (performance checklist)
1. **[P1] Size budget**: target roughly <=30 KB CSS and <=30 KB JS (pre-compression; files opened from disk are not gzip-transferred) for chrome; measure in CI and fail on regressions. The search index is the variable part: emit a compact structure (section id, title, plain text, maybe pre-tokenized terms), and parse it lazily on first focus of the search box (`JSON.parse` on demand) rather than at load.
2. **[P1] System fonts by default**: `font-family: system-ui, -apple-system, "Segoe UI", Roboto, "Noto Sans", sans-serif; code: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`. Embedding a WOFF2 subset as a data URI costs 20-100+ KB per face and blocks text until decoded; make it opt-in.
3. **[P1] No layout shift**: emit `width`/`height` for local images when the generator can read their dimensions (and `loading="lazy"`, `decoding="async"` for below-the-fold images); reserve space for the sticky header; apply the saved theme/text size in a blocking head script before first paint so nothing reflows after load.
4. **[P1] Large documents (thousands of headings)**: `content-visibility: auto; contain-intrinsic-size: auto 800px` on top-level sections (not on tiny elements); one delegated listener for copy buttons, glossary terms and figure zoom instead of per-element listeners; one IntersectionObserver for scroll-spy (or compute active heading from a sorted offset array on `scroll` with rAF); render the outline as plain nested lists (no per-item JS); build tooltips on demand (one shared tooltip element) rather than one per term.
5. **[P2] Avoid forced sync layout** in scroll handlers; use `passive: true` listeners.
6. **[P2] `content-visibility` caveat**: it can make `scrollIntoView` targets and scroll-spy measurements approximate until rendered; verify anchor jumps and Text Fragment jumps on very long pages.

### Gaps
- No authoritative published "size budget" exists for single-file documents; the numbers above are an inference, not a cited standard.

## 7. Validation tooling and CI for a generator

### Takeaway
Validate a corpus of fixture Markdown files (including hostile ones) on every commit: Nu HTML Checker (vnu) for conformance, html-validate for fast configurable lint, axe-core via Playwright for accessibility in every theme/preference combination, scripted keyboard tests for the custom widgets, a CSP-violation listener, and optional Lighthouse CI/pa11y-ci. Golden-file snapshot tests guard against accidental output changes.

### Cited Findings
- Nu HTML Checker (vnu) is the W3C/WHATWG conformance checker; runs as a Java jar, a Docker image, or an HTTP service, with JSON output for CI — [Nu Html Checker](https://validator.github.io/validator/)
- html-validate is an offline Node HTML validator with configurable rule sets (including accessibility rules) usable on files or strings — [html-validate](https://html-validate.org/)
- axe-core is an accessibility rules engine with Playwright integration (`@axe-core/playwright`) — [axe-core](https://github.com/dequelabs/axe-core); [@axe-core/playwright](https://www.npmjs.com/package/@axe-core/playwright)
- pa11y / pa11y-ci run automated accessibility checks (axe or HTML_CodeSniffer) against URLs or files in CI — [pa11y](https://github.com/pa11y/pa11y); [pa11y-ci](https://github.com/pa11y/pa11y-ci)
- Lighthouse audits accessibility, best practices and SEO; Lighthouse CI runs it on every commit — [Lighthouse overview](https://developer.chrome.com/docs/lighthouse/overview); [Lighthouse CI](https://github.com/GoogleChrome/lighthouse-ci)
- Playwright `page.emulateMedia()` can emulate `colorScheme`, `reducedMotion` and `forcedColors` — [Playwright emulateMedia](https://playwright.dev/docs/api/class-page#page-emulate-media)

### Inferences (CI checklist)
1. **[P0] Fixture corpus**: representative documents (all Markdown features, long doc with 2000+ headings, RTL doc, CJK doc, doc with glossary/figures/callouts/tables/code in many languages) plus an XSS corpus (javascript:/vbscript:/data: links in all spellings incl. entity- and percent-encoded and with embedded tabs/newlines, raw `<script>`, `<img onerror>`, inline SVG with script, `</script>` inside code and inside front matter, malicious heading text that becomes IDs/JSON). Assert no `on*` attributes, no `javascript:` in any URL attribute, and that the JSON index round-trips.
2. **[P0] vnu on every generated file**: `java -jar vnu.jar --errors-only --format json out/*.html` (or the Docker image); zero errors gate. Add `--also-check-css` for inline CSS.
3. **[P0] axe-core via Playwright** on each fixture, for each of: light, dark, system; `forcedColors: 'active'`; `reducedMotion: 'reduce'`; viewport 320 px and 1280 px; text size max. Include states: drawer open, tooltip open, zoom dialog open, search results open (axe checks only what is rendered).
4. **[P0] Keyboard scripts** (Playwright): Tab order starts with skip link; glossary term focus shows tooltip, Escape hides it and focus stays; zoom opens with Enter/Space, focus inside, Escape closes, focus restored; search arrows/Enter/Escape; copy button works and announces; no focus lands under the sticky header (compare focused element rect to header rect).
5. **[P0] CSP check**: open each output with Playwright, collect `securitypolicyviolation` events and console errors; any violation fails (catches stale hashes and accidental inline handlers). Also confirm zero network requests (`page.on('request')` only `file:`/`data:`).
6. **[P1] html-validate** as a fast pre-check in unit tests (can validate strings from Rust tests via a Node step or run on output dir), with rules for duplicate IDs, heading levels, `aria-*` validity, button types.
7. **[P1] Golden snapshot tests** in Rust (`insta` or similar) of generated HTML for fixtures, so any output change is reviewed.
8. **[P1] Cross-engine smoke**: run the Playwright suite on Chromium, Firefox and WebKit, from both `file://` and a local HTTP server (storage/clipboard/CSP behave differently).
9. **[P2] Lighthouse CI / pa11y-ci** on a few fixtures served over HTTP for a secondary opinion and score trend; contrast computed per theme token pair in a unit test (WCAG 2 formula) so palette edits can't regress silently.
10. **[P2] Manual screen-reader pass** per release with the matrix in section 1; automated tools find only part of WCAG failures.

### Gaps
- Exact current CLI flags for vnu, pa11y-ci and Lighthouse CI were not re-verified this session; check their READMEs when wiring CI.
- Whether Playwright's `emulateMedia` supports `prefers-contrast` was not verified.
